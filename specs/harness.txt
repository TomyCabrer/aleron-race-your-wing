##### HARNESS #####
SUMMARY:
Real-time keyboard/gamepad harness around the (separately specified) vehicle model. Fixed-timestep physics at 1000 Hz with an accumulator, decoupled 60 fps pygame top-down renderer, and a headless mode (SDL_VIDEODRIVER=dummy, verified working on this machine: driver='dummy', SysFont('Menlo') OK, 1280x800 surface OK) so every acceptance test runs without a window.

Three tracks are given as literal geometry: SKIDPAD (concentric guide circles R=30.48/50/75/100/130 m — the qss.py validation radii), DRAGSTRIP (1500 m straight with 1/8, 1/4 mile and standing-km gates plus a braking box), and CIRCUIT_ARENA, a closed 1249.202 m circuit whose seven corner radii are 45/30/80/55/110/35/130 m — deliberately spanning exactly the 30–130 m band, with T7 (R=130) the only power-limited corner (qss: 31.88 m/s power vs 33.17 m/s grip). Closure verified to 3.8e-8 m and 360.000000 deg; min self-clearance 66 m so a 12 m ribbon never overlaps. A quasi-steady lap solve over it using qss.max_ay gives an ideal lap of 53.7 s, which independently validates ledger.py's 60 s lap assumption.

Keyboard is made driveable by ramping the ROAD-WHEEL ANGLE at a physical hand rate (900 deg/s at the wheel / 16.0 = 56.25 deg/s at the road wheel; full lock 32.625 deg is reached in 0.58 s, which is 2.9 turns lock-to-lock at 900 deg/s — self-consistent), plus a speed-dependent soft limit delta_lim(V) built from the car's own steady-state cornering equation with a 15% margin, relaxed by body slip so the driver can still catch (or fail to catch) a slide. A --no-steer-limit path commands delta directly and is what the validation scripts use, so the aid never contaminates a test.

The flank wing produces only 63–227 N (R=50 to R=130, CL 0.70 to 1.25) against a ~9908 N car. That is 0.6–1.5% of corner speed. The harness therefore makes the effect legible NUMERICALLY (wing force in N drawn at the same px/N scale as the tyre-force vectors, live util_f/util_r computed with qss.fy_max itself, and a delta-time-vs-distance compare plot) rather than pretending it is felt through the seat.

Renderer costs were measured on this machine under the dummy driver: the track ribbon as ONE concave polygon is 0.58 ms/frame, whereas per-quad tessellation is 20.4 ms/frame and would miss 60 fps. That single measurement dictates the whole drawing strategy.

EQUATIONS:
  --- 1. FRAME LOOP (drive.py, interactive) ---
  dt_wall = clock.tick(FPS) / 1000.0
  dt_wall = min(dt_wall, MAX_FRAME_DT)                      # MAX_FRAME_DT = 0.10 s
  if first_frame or just_unpaused or just_reset: dt_wall = DT_PHYS; acc = 0.0
  acc = acc + dt_wall * time_scale                          # time_scale = 1.0, or 0.25 slow-mo
  n = 0
  while acc >= DT_PHYS and n < MAX_SUBSTEPS:  step_physics(DT_PHYS); acc -= DT_PHYS; n += 1
  if acc >= DT_PHYS:  dropped_s += acc; acc = 0.0; dropped_frames += 1   # bail out, never spiral
  alpha_render = acc / DT_PHYS                              # in [0,1)
  --- 2. HEADLESS LOOP (no wall clock anywhere -> bitwise deterministic) ---
  for i in range(int(round(T_total / DT_PHYS))):  step_physics(DT_PHYS)
  --- 3. INPUT RAMPS (integrated at DT_PHYS using key state sampled at 60 Hz) ---
  ramp(x, tgt, rise, fall, dt) = min(tgt, x + rise*dt) if tgt > x else max(tgt, x - fall*dt)
  throttle  = ramp(throttle,  1.0 if KEY_UP    else 0.0, 3.5, 6.0,  dt)
  brake     = ramp(brake,     1.0 if KEY_DOWN  else 0.0, 5.0, 8.0,  dt)
  clutch    = ramp(clutch,    1.0 if KEY_Z     else 0.0, 8.0, 3.0,  dt)
  handbrake = ramp(handbrake, 1.0 if KEY_SPACE else 0.0, 8.0, 10.0, dt)
  if FINE (LSHIFT held): throttle = min(throttle, 0.50); brake = min(brake, 0.50)
  --- 4. STEERING: ramp the ROAD-WHEEL angle, not a normalised axis ---
  d_in = (+1 if KEY_RIGHT else 0) + (-1 if KEY_LEFT else 0)      # note: RIGHT is -delta by SAE sign
  w_drv    = 900.0 / STEER_RATIO                                  # = 56.25 deg/s road wheel
  w_ret(V) = (720.0 + 720.0*clamp(V/22.0, 0, 1)) / STEER_RATIO    # = 45 -> 90 deg/s road wheel
  w_cnt(V) = w_drv + w_ret(V)                                     # = 101.25 -> 146.25 deg/s
  if FINE: all three rates are halved
  if d_in == 0:            delta_dot = -sign(delta) * w_ret(V);  snap to 0 if |delta| <= w_ret*dt
  elif d_in*delta < 0:     delta_dot = d_in * w_cnt(V)            # counter-steer / flick back
  else:                    delta_dot = d_in * w_drv
  delta = delta + delta_dot * dt
  --- 5. SPEED-DEPENDENT STEER LIMIT (driver aid; bypassed by --no-steer-limit) ---
  a_ref     = 1.15 * AY_MAX_DRY                                   # = 1.15*0.8624671*9.81 = 9.7299 m/s^2
  delta_ss(V) = degrees( L * a_ref / max(V, 3.0)**2 ) + K_US_DEG * (a_ref / G)
  delta_lim(V) = min(DELTA_LOCK_DEG, delta_ss(V))                 # DELTA_LOCK_DEG = 32.625
  beta_deg  = degrees( atan2(v_body, max(|u_body|, 0.5)) )
  delta_lim_eff = min(DELTA_LOCK_DEG, delta_lim(V) + 1.2*|beta_deg|)   # open up the lock in a slide
  delta = clamp(delta, -delta_lim_eff, +delta_lim_eff)
  --- 6. GAMEPAD (absolute axes: ramps bypassed, only a rate cap applied) ---
  dz(a, z) = 0.0 if |a| < z else sign(a)*(|a| - z)/(1.0 - z)      # z = 0.12 sticks, 0.05 triggers
  steer_axis = dz(axis[0], 0.12);  expo: g = sign(s)*|s|**1.5
  delta_target = delta_lim_eff * g
  delta = delta + clamp(delta_target - delta, -PAD_RATE*dt, +PAD_RATE*dt)   # PAD_RATE = 250 deg/s
  throttle = dz((axis[RT] + 1.0)/2.0, 0.05);  brake = dz((axis[LT] + 1.0)/2.0, 0.05)
  blend rule: if |pad_value| > 0.02 the pad wins that axis, else the keyboard ramp value is used
  --- 7. AUTO-CLUTCH / SHIFT STATE MACHINE (harness-side, feeds the vehicle model) ---
  launch:   if gear == 1 and V < 3.0:  clutch_auto = clamp(1.0 - V/3.0, 0, 1) * (1.0 - 0.6*throttle)
  stall guard: if gear != 0 and rpm < 1100:  clutch_auto = max(clutch_auto, clamp((1100-rpm)/600, 0, 1))
  shift (on edge, queue depth 1, ignored while busy):
    phase A 0.000-0.100 s: clutch 0->1 linear, throttle_out = 0 (upshift) or throttle_out = throttle (downshift)
    phase B 0.100-0.160 s: gear applied at t=0.100; throttle_out = 0.35 blip on downshift, 0 on upshift
    phase C 0.160-0.360 s: clutch 1->0 linear, throttle_out = throttle * smoothstep((t-0.160)/0.200)
  clutch_cmd = max(clutch_pedal, clutch_auto, clutch_shift)
  --- 8. FLANK WING ---
  wing_deploy_dot = (+1 if want_deployed else -1) / T_DEPLOY      # T_DEPLOY = 0.45 s
  d = clamp(wing_deploy + wing_deploy_dot*dt, 0, 1)
  f = d*d*(3.0 - 2.0*d)                                           # smoothstep, no force discontinuity
  k_eff = 0.5 * RHO * S_DEV * CL_DEV * f                          # RHO=1.2, S_DEV=0.35
  F_wing = k_eff * V*V                                            # N, +ve toward the inside of the corner
  D_wing = F_wing / LD_DEV                                        # LD_DEV = 3.2 (ledger.py)
  side selection (auto): side = -sign(delta) held through a 0.5 s hysteresis on |delta| < 0.5 deg
  applied by the vehicle model at x_w = 0.97 m (MOUNTS['front axle']), h_w = 0.90 m
  --- 9. TRACK CENTRELINE CONSTRUCTION (track.py, exact, DS = 0.5 m) ---
  straight seg: p(t) = p0 + t*[cos(psi0), sin(psi0)];  psi = psi0;  kappa = 0
  arc seg (turn_deg d, radius R, sgn = sign(d)):
    c   = p0 + sgn*R*[-sin(psi0), cos(psi0)]
    p(t)= c + Rot(sgn*t/R) @ (p0 - c);  psi = psi0 + sgn*t/R;  kappa = sgn/R
    arc_length = |radians(d)| * R
  left[i]  = xy[i] + (W/2)*[-sin(psi[i]),  cos(psi[i])]
  right[i] = xy[i] - (W/2)*[-sin(psi[i]),  cos(psi[i])]
  --- 10. NEAREST-POINT PROJECTION (grid hash, cell = 8.0 m) ---
  cand = union of grid buckets in the 3x3 (then 5x5, then full) neighbourhood of (x,y)
  i    = argmin_{j in cand} |xy[j] - p|
  refine on chord i-1..i and i..i+1:  u = clip( dot(p-xy[i], t_i)/|t_i|^2, -1, 1 )
  s = s[i] + u*DS   (wrapped mod length if closed)
  n = cross(t_hat_i, p - xy[i])                                   # +ve = LEFT of the centreline
  kappa_track = kappa[i];  psi_c = psi[i]
  --- 11. SURFACE ---
  on_track = |n| <= W/2
  mu_scale(p) = product over matching patches of patch.mu_scale, else 1.0 if on_track else MU_OFF (0.55)
  crr_scale(p) = 1.0 on track, CRR_OFF_SCALE = 25.0 off track (Crr 0.012 -> 0.30)
  patch matches if (s0 <= s <= s1, wrapped) and (n0 <= n <= n1)
  global wet override (key T / --wet all): mu_scale *= 0.632  (= 0.55/0.87, qss.sweep)
  --- 12. AXLE UTILISATION FOR THE HUD -- must import qss itself, not reimplement ---
  from qss import fy_max, TYRE      # TYRE = mu_ref 0.903, Fz_ref 2477.0, s -16.1e-6
  cap_f = fy_max(Fz_FL, mu_scale=mu_FL, **TYRE) + fy_max(Fz_FR, mu_scale=mu_FR, **TYRE)
  cap_r = fy_max(Fz_RL, mu_scale=mu_RL, **TYRE) + fy_max(Fz_RR, mu_scale=mu_RR, **TYRE)
  util_f = |Fy_FL + Fy_FR| / max(cap_f, 1.0)
  util_r = |Fy_RL + Fy_RR| / max(cap_r, 1.0)
  limited_by = 'FRONT' if util_f >= util_r else 'REAR'
  (display 'POWER' instead when throttle > 0.98 and max(util_f,util_r) < 0.90 and rpm > 0.85*RPM_PMAX)
  --- 13. CAMERA ---
  psi_err  = atan2( sin(psi - psi_cam), cos(psi - psi_cam) )      # wrap-safe
  psi_cam += psi_err * (1.0 - exp(-dt_frame / TAU_HEADING))       # TAU_HEADING = 0.12 s
  lead     = clamp(V * T_LEAD, 0.0, LEAD_MAX) * [cos(psi_cam), sin(psi_cam)]   # 0.6 s, 40 m
  cam_tgt  = p_car + lead
  ppm_raw  = PPM_HI + (PPM_LO - PPM_HI) * clamp(V / V_ZOOM, 0, 1)  # 14.0 -> 6.0 over 0..45 m/s
  ppm     += (ppm_raw*zoom_manual - ppm) * (1 - exp(-dt_frame/TAU_ZOOM))        # TAU_ZOOM = 0.35 s
  --- 14. WORLD -> SCREEN (numpy, (N,2) at a time; 5000 pts costs 0.12 ms) ---
  theta = -(psi_cam + pi/2) in car_up/chase mode, 0.0 in world_up mode
  Rm    = [[cos(theta), -sin(theta)], [sin(theta), cos(theta)]]
  anchor = (Wpx/2, Hpx*CAR_SCREEN_FRAC) in car_up/chase, (Wpx/2, Hpx/2) in world_up
  S = ((P - cam_tgt) @ Rm.T) * [ppm, -ppm] + anchor        # y flip: world +y is screen -y
  --- 15. RENDER-POSE INTERPOLATION (only the pose; HUD numbers use the latest state) ---
  p_draw   = p_prev + (p_now - p_prev) * alpha_render
  psi_draw = psi_prev + atan2(sin(psi_now-psi_prev), cos(psi_now-psi_prev)) * alpha_render
  --- 16. SKID MARK EMISSION (100 Hz, per wheel) ---
  emit if  |Fy_i| / max(fy_max(Fz_i, mu_scale=mu_i, **TYRE), 1.0) > 0.92  or  |kappa_i| > 0.12
  alpha_px = 150 * (1 - age / SKID_FADE_S)                        # SKID_FADE_S = 12.0
  draw with stride = max(1, ceil(n_visible / SKID_MAX_SEGS))      # SKID_MAX_SEGS = 600
  --- 17. LAP / SECTOR TIMING (sub-step accurate) ---
  crossing at s=S_line if (s_prev < S_line <= s_now) or (closed and s_prev > L-20 and s_now < 20)
  frac = (S_line - s_prev) / ((s_now - s_prev) mod L)
  t_cross = t_prev + frac * DT_PHYS
  lap_time = t_cross - t_cross_previous
  lap invalid if any physics step in the lap had all four wheels with |n_wheel| > W/2
  --- 18. g-g ENVELOPE OVERLAY (recomputed only when |V - V_cached| > 1.0 m/s) ---
  ay_env  = qss.max_ay(V, k=k_eff, x_w=X_W, h_w=H_W, mu_scale=mu_car)
  ax_accel(ay) = min( P_WHEEL/(m*max(V,3)), 0.90*ay_env ) * sqrt(max(0, 1-(ay/ay_env)**2)) - drag/m
  ax_brake(ay) = -( ay_env * sqrt(max(0, 1-(ay/ay_env)**2)) + drag/m )
  drag = 0.5*RHO*CdA*V*V + Crr*m*G
  --- 19. IDEAL-LAP REFERENCE SOLVER (validation only, drive/ideal_lap.py) ---
  V_lim[i] : solve V = V + 0.3*(sqrt(max_ay(V)*1/|kappa_i|) - V), 200 iters; = Vmax where kappa=0
  forward:  V[i+1] = min(V[i+1], sqrt(V[i]^2 + 2*ax_fwd*DS)), 2 wraps
  backward: V[i-1] = min(V[i-1], sqrt(V[i]^2 + 2*ax_bwd*DS)), 2 wraps
  t_lap = sum(DS / V[i])

PARAMETERS:
  DT_PHYS = 0.001 [s] (derived) :: derived. Measured: qss-grade MF Fy0 in pure python is 1.95 us/call on this machine, so 4 wheels x 1000 Hz costs 0.0078 s per simulated second for the tyre alone; a full combined-slip step budgeted at 150 us gives RTF ~6.7. Also needs to resolve tyre relaxation (sigma/V = 0.4/30 = 13 ms) and wheel-spin lock/unlock transients with explicit integration.
  DT_PHYS_FALLBACK = 0.002 [s] (derived) :: 500 Hz fallback selected by --dt if the RTF acceptance test (V8) fails on slower hardware. Must be re-validated against tests V1-V4 because wheel-spin stability is dt sensitive.
  MAX_SUBSTEPS = 40 [steps/frame] (derived) :: derived: one 60 fps frame is 16.7 ms = 16.7 steps; 40 allows 2.4x catch-up before time is dropped. Above this the loop bails rather than spiralling.
  MAX_FRAME_DT = 0.10 [s] (derived) :: derived: caps a window drag / GC pause / debugger break at 100 ms of integrated time.
  FPS = 60 [Hz] (published) :: requirement
  TELEM_HZ = 100 [Hz] (derived) :: chosen: every 10th physics step at 1 kHz; resolves the 0.36 s shift event and 0.45 s wing deploy with >30 samples each. ~3.6 MB/min at 60 columns.
  SURFACE_LOOKUP_HZ = 200 [Hz] (derived) :: derived: at 33 m/s a wheel moves 0.17 m per update, finer than any painted surface boundary. Car-body projection still runs at the full 1 kHz for lap timing.
  WINDOW_SIZE = 1280 x 800 [px] (estimated) :: chosen; fits a MacBook panel. All HUD rects are given in these base units and multiplied by ui_scale = min(W/1280, H/800).

@dataclass(frozen=True)
class Seg:

  @dataclass(frozen=True)
class SurfacePatch:
    s0: float; s1: float          # arclength window, m (wraps if s1 < s0 on a closed track)
    n0: float; n1: float          # lateral window, m, +ve = LEFT of centreline
    mu_scale: float = 1.0
    crr_scale: float = 1.0
    label: str = ''
    colour: tuple = (43, 58, 74)
      A rectangular-in-(s,n) surface region. Overlapping patches multiply their mu_scale. Used for the wet and split-mu regions listed in the parameters.
  @dataclass
class Track:
    name: str
    width: float
    segs: list[Seg]
    origin: tuple[float, float]
    heading0: float
    closed: bool
    surfaces: list[SurfacePatch] = field(default_factory=list)
    sector_s: list[float] = field(default_factory=list)
    guide_radii: list[float] = field(default_factory=list)   # skidpad only
    gates: list[tuple[float, str]] = field(default_factory=list)  # dragstrip only
    # built by build(): s, xy, psi, kappa, left, right : np.ndarray; length: float; bbox: tuple
      Immutable track description plus the sampled arrays built from it at DS = 0.5 m. xy/left/right are (N,2) float64; s/psi/kappa are (N,).
  def build(tr: Track) -> Track
      Integrates segs from origin/heading0 at DS = 0.5 m, fills xy/psi/kappa/left/right/s/length/bbox, and builds the 8.0 m projection grid hash. Asserts closure for closed tracks: norm(xy[-1] - xy[0]) < 1e-4 m and abs(sum(turn_deg) - 360) < 1e-6.
  def project(tr: Track, x: float, y: float) -> tuple[float, float, float, float, int]
      Returns (s, n, kappa_track, psi_c, i). n is +ve to the LEFT of the centreline. Grid-hashed 3x3 -> 5x5 -> full-argmin fallback, then refined by projecting onto the two adjacent chords. Must be < 20 us per call; it runs 1000/s for the car body and 800/s for the wheels.
  def surface_at(tr: Track, x: float, y: float, global_wet: float = 1.0) -> tuple[float, float, bool]
      Returns (mu_scale, crr_scale, on_track). Applies patch products, then the off-track MU_OFF_TRACK = 0.55 / CRR_OFF_SCALE = 25.0, then multiplies by global_wet (1.0 dry, 0.632183908 wet). Called per wheel at SURFACE_LOOKUP_HZ = 200 and the result held between updates.
  def start_pose(tr: Track, offset_n: float = 0.0) -> tuple[float, float, float]
      Returns (x, y, psi) on the centreline at s = 0 offset laterally by offset_n. For SKIDPAD returns (cx + R, cy, +pi/2).
  def point_at(tr: Track, s: float, n: float = 0.0) -> tuple[float, float]
      Inverse of project(); used by the round-trip acceptance test and by the scripted path-following controllers.

class VehicleState(Protocol):
    x: float; y: float; psi: float          # m, m, rad (world)
    u: float; v: float; r: float            # m/s, m/s, rad/s (body: u fwd, v left)
    ax: float; ay: float                    # m/s^2, body axes, at the CG
    Fz: np.ndarray; Fx: np.ndarray; Fy: np.ndarray   # (4,) N, order FL, FR, RL, RR
    alpha: np.ndarray; kappa: np.ndarray    # (4,) rad, -
    delta_wheel: np.ndarray                 # (4,) rad, actual steer per wheel
    omega_wheel: np.ndarray                 # (4,) rad/s
    rpm: float; gear: int                   # gear 0 = neutral, -1 = reverse
    engaged: bool                           # clutch fully engaged
    F_wing: float; wing_side: int           # N (magnitude), -1 left / 0 none / +1 right

class Vehicle(Protocol):
    state: VehicleState
    def reset(self, x: float, y: float, psi: float, V: float = 0.0, gear: int = 1) -> None: ...
    def step(self, ctl: 'Controls', mu: np.ndarray, crr: np.ndarray, dt: float) -> None: ...
      The ONLY coupling between the harness and the physics. mu and crr are (4,) per-wheel surface scales supplied by the harness from surface_at(). The harness never reaches inside the model. If the model cannot supply a field, it must expose it as NaN rather than omitting it, so the telemetry schema stays fixed.

  class InputSource(Protocol):

class ScriptedInput(InputSource):

PITFALLS:
  - THE RIBBON MUST BE ONE POLYGON. Measured on this machine: 400 filled quads per frame costs 20.41 ms and misses 60 fps outright; a single 700-point concave polygon built from the visible left edge plus the reversed right edge costs 0.58 ms. pygame.draw.polygon handles concave outlines correctly. Do not tessellate the track per centreline interval, and do not pre-render the whole track and rotate it per frame (subsurface rotate+blit measured 2.3-6.7 ms and forces a fixed zoom).
  - SKID MARKS ARE THE ONLY UNBOUNDED DRAW COST. 1500 individual pygame.draw.line calls measured 8.66 ms per frame, half the entire 16.7 ms budget. Cap visible segments at 600 by strided subsampling of the deques (stride = ceil(n_visible / 600)) and cull to the camera radius BEFORE transforming. Symptom if ignored: fps degrades progressively during a session and the user blames the physics.
  - PYGAME'S FIRST FRAME ON macOS CAN BE 0.5-2 s. Feeding that into the accumulator runs 500-2000 physics steps in one go and the car is somewhere else before the first frame is drawn. Fix: force dt_wall = DT_PHYS and acc = 0 on the first frame after init, after any reset, and after unpausing. Same applies after a window drag (the loop is blocked entirely by the OS) and after a GC pause; MAX_FRAME_DT = 0.10 s catches those.
  - SDL_VIDEODRIVER MUST BE SET BEFORE pygame IS IMPORTED ANYWHERE IN THE PACKAGE, not just before pygame.display.init(). If drive/render.py does a module-level 'import pygame' and drive/drive.py sets the env var in main(), the dummy driver silently does not take effect under pytest (which imports the package first) and CI tries to open a window. Fix: set os.environ in drive/__init__.py guarded by a CARSIM_HEADLESS env var, or set it at the very top of the test conftest. Also set SDL_AUDIODRIVER=dummy to avoid CoreAudio init. Verified: with dummy set correctly, get_driver() == 'dummy', set_mode, SysFont('Menlo') and flip all work on this machine.
  - DO NOT RAMP A NORMALISED STEER AXIS. Mapping a [-1,1] axis onto full lock (32.625 deg) and ramping that gives a car that is undriveable above 15 m/s: at 29 m/s the whole usable range is the first 15% of the axis. Ramp the ROAD-WHEEL ANGLE at a hand rate (900 deg/s / 16.0 = 56.25 deg/s) and clamp it with the speed-dependent delta_lim(V). The two are not equivalent and the difference is the whole feel of the sim.
  - THE STEER LIMITER MUST OPEN UP WITH BODY SLIP OR THE CAR CANNOT BE CAUGHT. delta_lim(30 m/s) = 4.72 deg; a 12 deg slide needs roughly 10-15 deg of opposite lock. Without the +1.2*|beta_deg| term every slide becomes an unrecoverable spin and the user concludes the physics is broken when it is the input layer. Conversely, do NOT apply the limiter in any validation script: run those with steer_limit=False so the aid never contaminates a measured number.
  - UTILISATION MUST IMPORT qss.fy_max, NOT REIMPLEMENT IT. The whole point of the HUD's util_f / util_r / limited_by is that it is directly comparable with qss.residuals(). Retyping mu = 0.903 - 16.1e-6*(Fz - 2477) in render.py guarantees a slow drift as one file is edited and the other is not, and V28 will fail for a reason nobody can find. from qss import fy_max, TYRE.
  - THE WING EFFECT IS 0.6-1.5% AND WILL NOT BE FELT. 62.9 N at R=50 against a 9908 N car. If the implementer scales the wing's force arrow differently from the tyre arrows to 'make it visible', the sim lies about the central result of the study. Draw both at the same px/N and let the wing arrow be 3 px. Legibility comes from the numeric HUD (F_wing in N, live util_f/util_r delta) and from plots.compare(by='distance'), which is the only view that resolves a 0.6% corner-speed gain.
  - AN INSTANTANEOUS WING TOGGLE PUTS A STEP IN THE LATERAL FORCE AND A SPIKE IN THE YAW ACCELERATION. At 29 m/s the plate is 227 N applied 0.97 m ahead of the CG: a 220 N-m step into Izz = 1200 kg m^2. It will look like a bug. Ramp the deploy over 0.45 s with a smoothstep so dF/dt is zero at both ends (V19).
  - OFF-TRACK WITH NO GROUND TEXTURE GIVES NO SPEED CUE. A top-down car on a flat background at constant heading looks stationary. Draw a 20 m grid in BG_OFFTRACK+GRID over the whole visible area before anything else. Cheap (two strided line families) and it is the difference between a driveable and an unreadable view.
  - SURFACE mu MUST BE LOOKED UP PER WHEEL. A single car-centre lookup silently deletes split-mu, which is the only reason the DAMP_T5_EXIT and dragstrip split patches exist and is the most interesting thing a wet surface can do to a FWD car under braking. Four lookups at 200 Hz is 800 project() calls per second, roughly 1% of one core.
  - THE NEAREST-SAMPLE PROJECTION FAILS SILENTLY FAR OFF TRACK. If the 3x3 grid neighbourhood is empty, argmin over an empty candidate list raises, or worse a stale index is reused and n jumps sign. Implement the 3x3 -> 5x5 -> full-argmin fallback explicitly and unit-test it at a point 200 m outside the circuit. Also: on a closed track s must wrap, so the chord refinement at i = 0 and i = N-1 needs modular indexing or the car's s glitches to 1249 m every lap and the lap timer fires twice.
  - LAP DETECTION BY 'DID s DECREASE' DOUBLE-FIRES. Lateral noise near the start line and the wrap discontinuity both look like a crossing. Require (s_prev > length - 20 and s_now < 20) for the wrap case, add a 3 s minimum lap time lockout, and interpolate the crossing fraction (V25 needs 0.002 s accuracy, better than one physics step).
  - INTEGRATING THE INPUT RAMPS AT THE RENDER RATE MAKES THE CAR FRAME-RATE DEPENDENT. Sample key state at 60 Hz (that is all pygame gives you) but integrate the ramps inside step_physics at DT_PHYS with the held state. Otherwise the same key press produces different steering on a 60 fps and a 45 fps machine, and V20 determinism fails the moment anyone runs interactively.
  - CSV WRITING WILL DOMINATE THE PHYSICS BUDGET IF DONE PER ROW. 100 Hz x 63 columns through csv.writer one row at a time with a flush is far more expensive than the physics step it logs. Buffer 200 rows and use writerows; open with newline='' or every line gets a stray \r on some tooling. Format with f'{v:.6g}' by default — repr() roughly doubles file size — but the determinism test must use full precision or it compares rounded values and passes vacuously.
  - matplotlib WILL TRY TO OPEN A WINDOW. drive/plots.py must call matplotlib.use('Agg') before importing pyplot, or importing it inside a headless test run hangs or crashes on macOS. Do not use pandas anywhere in this module; csv + numpy is enough and pandas is not in the verified dependency list.
  - THE g-g ENVELOPE CALLS qss.max_ay, WHICH BISECTS 200 TIMES PER CALL. Calling it every frame per axis point is thousands of bisections a second. Cache the envelope curve and recompute only when |V - V_cached| > 1.0 m/s; that is 1-3 recomputes per second in normal driving.
  - FONT RENDERING IS 30-60 us PER STRING AND THE HUD HAS ~30 OF THEM. That is 1.5 ms a frame of pure text. Cache every static label surface at startup, and cache numeric surfaces keyed on the QUANTISED value (speed to 1 km/h, rpm to 50, forces to 10 N) so the cache actually hits instead of missing on every float.
  - DRAWING SLIP AND FORCE VECTORS FROM THE WHEEL CENTRE INSTEAD OF THE CONTACT PATCH looks fine until the car is sliding, when the arrows visibly lead or lag the tyre. Anchor them at the contact patch position in the body frame, transform with the same matrix as everything else, and remember world +y maps to screen -y so a naive rotation puts every lateral force on the wrong side.
  - TIME_SCALE AND SLOW-MO MUST MULTIPLY dt_wall, NOT DT_PHYS. Changing DT_PHYS at runtime changes the integration accuracy and can destabilise the wheel-spin ODE mid-corner. Slow-mo is acc += dt_wall * 0.25 with DT_PHYS untouched.
  - THE CAR-UP CAMERA ROTATION SIGN IS EASY TO GET BACKWARDS AND THE BUG IS SUBTLE. theta = -(psi_cam + pi/2). Test it by placing the car at psi = 0 (heading world +x) and asserting a point 10 m directly ahead of it lands directly ABOVE the car anchor on screen. Getting it wrong by pi/2 produces a sim that drives sideways and is often mistaken for a physics sign error.
  - K_US_DEG = 3.2 IS A GUESS INSIDE THE INPUT LAYER. It sets delta_lim only, never the physics, but if it is far from the vehicle model's true understeer gradient the steering will feel either capped (too small) or vague (too large). Once the model runs, measure its actual steady-state road-wheel angle at the R=50 limit — the target is 5.614 deg — and set K_US_DEG = (delta_measured - degrees(2.491/50)) / 0.8625.
  - SHIFT AND WING KEYS MUST BE EDGE-TRIGGERED, NOT LEVEL-TRIGGERED. Reading pygame.key.get_pressed() for E/Q/F in the physics loop at 1 kHz fires a thousand shift requests per key press. Consume them from the pygame event queue in poll_events() (KEYDOWN only), queue at most one pending shift, and ignore new requests while a shift is in progress.
