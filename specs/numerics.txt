##### NUMERICS #####
SUMMARY:
Physics runs at a FIXED 1000 Hz (dt = 1.0e-3 s) with a render-decoupled accumulator, using semi-implicit (staggered/symplectic) Euler for the rigid body and wheels, an EXACT exponential update for the tyre carcass-deflection (relaxation) states, and an IMPLICIT update for the wheel spin when the low-speed damper is active. This choice is not a guess: the fastest mode in the whole car is the tyre-carcass/wheel-inertia mode at wn = r*sqrt(C_long/Iw) = 0.283*sqrt(381913/0.75) = 201.9 rad/s = 32.1 Hz, and — crucially — that frequency is INDEPENDENT of load and of speed, because both K_x and sigma_x scale with Fz. Everything else is slower: roll 9.09 rad/s (1.45 Hz), yaw/sideslip 3.6-95 s^-1, tyre relaxation lag 2.6-250 ms. I measured the stability boundary directly (free-rolling wheel with a 2% kappa perturbation): the staggered ordering is stable to dt = 8 ms and diverges at 12 ms; the naive ordering (force from the OLD kappa, then kappa from the OLD omega) diverges at dt >= 4 ms at V = 25 m/s and at EVERY dt tested (down to 0.5 ms) at V = 3 m/s. dt = 1 ms therefore gives h*wn = 0.202, an 8x margin, at one force evaluation per step — strictly better value than RK4 at 250 Hz (4 evaluations, same cost, and RK4 collapses to first order anyway across the wheel-lock discontinuity). The V->0 singularity is removed structurally: kappa = Vsx/Vx is NEVER formed; the transient slip states are integrated from sigma*d(k')/dt = -|Vx|*k' + Vsx, in which Vx appears only as a multiplier. A Besselink low-speed damper (V_low = 2.5 m/s) supplies the missing damping so the car holds on a slope without jitter. I built a working prototype of exactly this model and validated it against qss.py: peak lateral acceleration 0.8545 g vs qss 0.862467 g (-0.92%, entirely explained by the cos(delta) projection that qss omits — force cos(delta)=1 and it reads 0.8614 g, -0.13%), front/rear axle utilisation 0.998/0.944 vs qss 1.000/0.952, corner speeds -0.43% to -0.58% of qss at R = 50/100/130 m, and wing gains matching qss to 0.1 pp at the CG mount. All 24 acceptance tests below carry numbers I actually ran today.

EQUATIONS:
  --- 0. NOTATION. Body frame x forward, y left, z up. Wheels indexed j = 0..3 = FL,FR,RL,RR. All angles rad internally. State vector: X,Y,psi (ground pose); u,v,r (body velocities); phi,phidot (roll); omega[4]; kx[4] (transient longitudinal slip); ky[4] (transient tan of slip angle); we (engine speed); gear; clutch.
  --- 1. WHEEL CONTACT-POINT VELOCITIES (evaluated first, from the CURRENT state) ---
  y_w = [ +t_f/2, -t_f/2, +t_r/2, -t_r/2 ]   with t_f = 1.429, t_r = 1.420
  x_w_j = [ +a, +a, -b, -b ]                 with a = 0.97149, b = 1.51951
  Vcx_j = u - r*y_w_j   ;   Vcy_j = v + r*x_w_j        (contact point velocity, body frame)
  delta_j = delta for j in {0,1}, 0 for j in {2,3}     (no rear steer; Ackermann optional, see eq. 44)
  Vx_j =  Vcx_j*cos(delta_j) + Vcy_j*sin(delta_j)      (wheel frame, longitudinal)
  Vy_j = -Vcx_j*sin(delta_j) + Vcy_j*cos(delta_j)      (wheel frame, lateral)
  Vsx_j = omega_j*r_roll - Vx_j                        (longitudinal slip velocity, m/s)
  Vsy_j = Vy_j                                          (lateral slip velocity, m/s)
  --- 2. VERTICAL LOADS (a_y and a_x are the PREVIOUS step's values; lag costs <0.05% at 1 kHz) ---
  F_w = k_wing * u*u * wing_on                          (flank-wing side force, N; k_wing = 0.147 clean fin, 0.2625 sealed plate)
  s_wing = tanh( ay_filt / 1.0 )                        (which flank works; ay_filt = 1st-order lag, tau 0.15 s. NEVER sign())
  dFz_lat = ( m*a_y*h_cg - F_w*h_w ) / t_bar            with t_bar = 0.5*(t_f+t_r) = 1.42450, h_cg = 0.55, h_w = 0.90
  dFz_lon = m*a_x*h_cg / L                              with L = 2.491
  Fz_0 = m*g*wdist_f - dFz_lon   (front axle total)  ;  Fz_1 = m*g*(1-wdist_f) + dFz_lon   (rear axle total)
  Fz[0] = max( Fz_0/2 + dFz_lat*roll_dist_f      , 0 )   with roll_dist_f = 0.74
  Fz[1] = max( Fz_0/2 - dFz_lat*roll_dist_f      , 0 )
  Fz[2] = max( Fz_1/2 + dFz_lat*(1-roll_dist_f)  , 0 )
  Fz[3] = max( Fz_1/2 - dFz_lat*(1-roll_dist_f)  , 0 )
  # NOTE: use t_bar and roll_dist_f exactly as above -- this is qss.py's formulation. A 'more physical' per-axle-track roll-stiffness split will miss test T5/T6 by ~1%.
  --- 3. TYRE COEFFICIENTS (pure functions of Fz; precompute a 64-point lookup on Fz in [0, 8000] N, linear interpolation) ---
  mu_y(Fz) = max( 0.903 - 16.1e-6*(Fz - 2477.0) , 0.05 )      <- qss.TYRE, this is the reference truth
  mu_x(Fz) = 1.10 * mu_y(Fz)
  K_ya(Fz) = 14.9773 * 4000 * sin( 1.9896 * atan( Fz / (1.7044*4000) ) )        [N/rad]
  K_xk(Fz) = Fz * (21.69 + 13.774*dfz) * exp(-0.4119*dfz),  dfz = (Fz-4000)/4000  [N per unit slip]
  sigma_x(Fz) = clamp( K_xk(Fz) / 381913.4 , 0.05 , 0.40 )     [m]   (C_long from TNO_car205_60R15.tir)
  sigma_y(Fz) = clamp( K_ya(Fz) / 157632.5 , 0.10 , 0.50 )     [m]   (C_lat  from the same file)
  Ksx(Fz) = Bx*Cx*mu_x(Fz)*Fz / K_xk(Fz)      (= kappa at the peak)
  Ksy(Fz) = By*Cy*mu_y(Fz)*Fz / K_ya(Fz)      (= tan(alpha) at the peak)
  --- 4. TRANSIENT SLIP (exact exponential; this is the whole low-speed fix) ---
  ax_j = -|Vx_j| / sigma_x(Fz_j)   ;   cx_j = Vsx_j / sigma_x(Fz_j)
  kx_j <- kx_j*exp(ax_j*dt) + (cx_j/ax_j)*(exp(ax_j*dt) - 1)        if |ax_j*dt| > 1e-6
  kx_j <- kx_j + cx_j*dt                                             otherwise (exact limit at Vx = 0)
  ay_j = -|Vx_j| / sigma_y(Fz_j)   ;   cy_j = Vsy_j / sigma_y(Fz_j)
  ky_j <- ky_j*exp(ay_j*dt) + (cy_j/ay_j)*(exp(ay_j*dt) - 1)   (same 1e-6 fallback)
  kx_j <- clamp(kx_j, -1.5, 1.5)   ;   ky_j <- clamp(ky_j, -3.0, 3.0)
  --- 5. TYRE FORCES: one fixed shape function, peak exactly 1.0 at rho = 1 ---
  f(rho, B, C, E) = sin( C * atan( B*rho - E*(B*rho - atan(B*rho)) ) )
  # B is chosen so f peaks at rho = 1:  B - E*(B - atan(B)) = tan(pi/(2C))
  Cy = 1.3332, Ey = -0.43  ->  By = 2.023121   (slide/peak ratio sin(Cy*pi/2) = 0.8661)
  Cx = 1.5000, Ex = +0.28  ->  Bx = 1.976883   (slide/peak ratio sin(Cx*pi/2) = 0.7071)
  sx_j = kx_j / Ksx(Fz_j)   ;   sy_j = ky_j / Ksy(Fz_j)   ;   rho_j = sqrt(sx_j^2 + sy_j^2)
  if rho_j < 1e-9:  Fx_t = 0, Fy_t = 0
  else: Fx_t_j = + (sx_j/rho_j) * f(rho_j,By,Cy,Ey) * mu_x(Fz_j) * Fz_j     <- PLUS sign
        Fy_t_j = - (sy_j/rho_j) * f(rho_j,By,Cy,Ey) * mu_y(Fz_j) * Fz_j     <- MINUS sign
  # The sign asymmetry is real: kappa>0 pushes the car FORWARD, alpha>0 pushes it to -y. Getting this wrong is silent and fatal.
  # The elliptical projection guarantees sqrt((Fx/(mu_x Fz))^2 + (Fy/(mu_y Fz))^2) <= 1 and exact pure-slip peaks.
  --- 6. LOW-SPEED (BESSELINK) DAMPER ---
  kv_j = 0.5 * (K_xk(Fz_j)/V_low) * (1 + cos(pi*|Vx_j|/V_low))   if |Vx_j| < V_low else 0     with V_low = 2.5 m/s
  kvy_j = 0.5 * (K_ya(Fz_j)/V_low) * (1 + cos(pi*|Vx_j|/V_low))  if |Vx_j| < V_low else 0
  Fx_j = Fx_t_j + kv_j * Vsx_j        (damper applied IMPLICITLY on omega, see eq. 7)
  Fy_j = Fy_t_j - kvy_j * Vsy_j
  --- 7. WHEEL SPIN (semi-implicit; the damper term must be on the left-hand side) ---
  T_drive_j = T_clutch * n_gear * eta_drive * 0.5  for j in {0,1} (FWD, open diff), 0 for j in {2,3}
  T_brake_j = pedal_torque_j * tanh( omega_j / 1.0 )      <- smooth zero crossing, omega_eps = 1.0 rad/s
  I_eff_j = Iw_j + (Ie * n_gear^2 * 0.5) * clutch_locked   for j in {0,1};  Iw_j for j in {2,3}
  omega_j <- ( omega_j + (dt/I_eff_j)*( T_drive_j - T_brake_j - r_roll*Fx_t_j + kv_j*r_roll*Vx_j ) ) / ( 1 + dt*kv_j*r_roll^2/I_eff_j )
  if omega_j * omega_j_previous < 0 and T_drive_j == 0:  omega_j <- 0      (lock latch, see pitfalls)
  --- 8. BODY FORCES (project wheel forces back to the body frame) ---
  Fbx_j = Fx_j*cos(delta_j) - Fy_j*sin(delta_j)   ;   Fby_j = Fx_j*sin(delta_j) + Fy_j*cos(delta_j)
  F_aero_x = -0.5*rho_air*CdA*u*|u| - (k_wing/3.2)*u*u*wing_on          (rho_air = 1.2, CdA = 0.66, device L/D = 3.2)
  F_roll_x = -Crr*m*g*tanh(u/0.3)                                        (Crr = 0.012)
  SumFx = sum(Fbx_j) + F_aero_x + F_roll_x
  SumFy = sum(Fby_j) + s_wing*F_w
  SumMz = sum( x_w_j*Fby_j - y_w_j*Fbx_j ) + s_wing*F_w*x_wing
  --- 9. RIGID-BODY UPDATE (semi-implicit Euler: velocities first, then pose from the NEW velocities) ---
  u <- u + dt*( SumFx/m + v*r )
  v <- v + dt*( SumFy/m - u*r )
  r <- r + dt*( SumMz/Izz )
  a_x = SumFx/m   ;   a_y = SumFy/m          (store for the NEXT step's load transfer)
  X <- X + dt*( u*cos(psi) - v*sin(psi) )  ;  Y <- Y + dt*( u*sin(psi) + v*cos(psi) )  ;  psi <- psi + dt*r
  --- 10. ROLL DOF (visual + rear roll-steer/camber only; does NOT feed load transfer) ---
  I_roll = Ixx + m_s*(h_cg - h_ra)^2 = 267 + 892*0.39^2 = 402.7 kg m^2   (h_ra = 0.160 m)
  M_roll = m_s*a_y*(h_cg - h_ra) - F_w*(h_w - h_ra) + m_s*g*(h_cg-h_ra)*phi - K_phi*phi - C_phi*phidot
  phidot <- phidot + dt*M_roll/I_roll   ;   phi <- phi + dt*phidot        (K_phi = 36669 Nm/rad, C_phi = 2928 Nm s/rad)
  --- 11. ENGINE / CLUTCH ---
  rpm = we*60/(2*pi)  ;  T_eng = interp(rpm, RPM_TABLE, TRQ_TABLE) * throttle
  if clutch_locked:  we = 0.5*(omega_0+omega_1) * n_gear
  else:              we <- we + dt*( T_eng - T_clutch )/Ie ,  we <- max(we, 80.0)   (~764 rpm idle floor)
  T_clutch = clutch_capacity * clutch_pedal_engagement,  capacity = 180 Nm
  lock when |we - 0.5*(omega_0+omega_1)*n_gear| < 2.0 rad/s AND capacity >= T_eng ; unlock when |T_required| > capacity
  --- 12. STEERING ---
  delta = steer_input * delta_max,  delta_max = 35 deg / steer_ratio = 35/16 -> use delta_max = 0.5236 rad (30 deg) at the road wheel
  steer rate limit: |d(delta)/dt| <= 8.0 rad/s at the road wheel (a human cannot turn a wheel faster than ~2 turns/s)
  --- 13. THE FLANK-WING DELTA (the thing the user must FEEL) ---
  k_wing = 0.5 * rho_air * S_dev * CL_dev ;  S_dev = 0.35 m^2 ;  CL_dev = 0.70 (clean fin) or 1.25 (sealed plate)
  F_w(29.087 m/s) = 0.147 * 846.1 = 124.4 N ; yaw moment at x_wing = +0.97 m -> 120.6 Nm ; roll moment about h_ra -> 92.1 Nm
  deployed mass penalty: m += 39 kg at x_wing, h_w -> recompute wdist_f, h_cg, Izz (parallel axis) ONCE at deploy, not every step

  guard: max |r| (yaw rate) = 6.0 [rad/s] (estimated) :: Estimated. A spinning car reaches ~2-3 rad/s; 6 rad/s (one revolution per second) is a numerical failure.
  V_stick (full-stop latch) = 0.05 m/s enter, 0.15 m/s exit [m/s] (estimated) :: Estimated. Belt-and-braces on top of the Besselink damper; 3:1 hysteresis.

API:
  @dataclass
class VehicleState:
    X: float; Y: float; psi: float
    u: float; v: float; r: float
    phi: float; phidot: float
    omega: list[float]      # 4, rad/s, FL FR RL RR
    kx: list[float]         # 4, transient longitudinal slip (dimensionless)
    ky: list[float]         # 4, transient tan(slip angle)
    we: float               # engine speed, rad/s
    gear: int               # -1 reverse, 0 neutral, 1..5
    clutch_locked: bool
    ax: float; ay: float    # previous-step accelerations, for load transfer
    ay_filt: float          # lagged ay, for the wing side-selection tanh
    delta: float            # current road-wheel steer, rad (rate-limited)
    t: float
      The complete integrated state. 26 scalars. Everything else (Fz, forces, slip angles for display) is DERIVED and must not be stored across steps -- if the implementer caches a force, the staggered ordering silently breaks and the wheel mode diverges.
  @dataclass
class DriverInput:
    steer: float        # -1..+1
    throttle: float     # 0..1
    brake: float        # 0..1
    clutch: float       # 0..1, 1 = fully depressed
    handbrake: float    # 0..1, rear axle only
    shift_up: bool; shift_down: bool
    wing_deploy: bool
      One frame of driver demand. The keyboard layer produces this with its own smoothing (ramp steer at 8 rad/s max at the road wheel, throttle/brake first-order lag tau = 0.08 s); integrate.py must NOT do input smoothing itself or the ramp-steer validation test cannot drive delta directly.
  @dataclass
class SimConfig:
    dt: float = 1.0e-3
    max_substeps: int = 8
    wing_on: bool = False
    k_wing: float = 0.147
    x_wing: float = 0.97
    h_wing: float = 0.90
    wing_mass: float = 39.0
    force_cos_delta: bool = True     # set False to reproduce qss.py exactly (test T6b)
    mu_scale: float = 1.0            # 0.632 for wet, matching qss's 0.55/0.87
    abs_enabled: bool = False
    guards_enabled: bool = True
      Everything the validation harness needs to flip. force_cos_delta=False is not a physics option, it is a DIAGNOSTIC: it removes the front-tyre-to-body projection that qss.py omits, and it is the single switch that converts a -0.92% disagreement with qss into a -0.13% one. Ship it.
  def step(state: VehicleState, inp: DriverInput, car: CorsaC, cfg: SimConfig) -> tuple[VehicleState, Telemetry]
      Advance the state by exactly cfg.dt. Pure: returns a new state, mutates nothing. Order inside is fixed and load-bearing: (1) contact velocities from the CURRENT state, (2) Fz, (3) tyre coefficients, (4) exponential update of kx/ky from the CURRENT omega, (5) tyre forces from the NEW kx/ky, (6) implicit omega update, (7) body update, (8) roll, (9) engine/clutch, (10) pose from the NEW velocities. Swapping (4) and (5)/(6) is the failure mode that diverges at every dt below 8 ms.
  def advance(state: VehicleState, inp: DriverInput, car: CorsaC, cfg: SimConfig, frame_dt: float, accumulator: float) -> tuple[VehicleState, float, Telemetry]
      Fixed-timestep accumulator for the render loop. acc += frame_dt; while acc >= dt and n < max_substeps: state = step(...); acc -= dt. If max_substeps is hit, DISCARD the remaining accumulator (spiral-of-death guard) and set Telemetry.dropped_steps. Never scale dt to the frame time -- a variable dt changes the car's measured limit by up to 0.2% and makes the validation suite non-reproducible.
  def tyre_forces(Fz: float, kx: float, ky: float, mu_scale: float) -> tuple[float, float]
      Pure-slip and combined-slip tyre force from the TRANSIENT slip states. Returns (Fx, Fy) in the wheel frame, N. Must return exactly (0.0, 0.0) for Fz <= 0. This is the only place mu_y, mu_x, Ksx, Ksy and f(rho) appear.
  def tyre_coeffs(Fz: float) -> TyreCoeffs   # mu_y, mu_x, K_ya, K_xk, sigma_x, sigma_y, Ksx, Ksy
      Load-dependent tyre coefficients. Implement as a 64-point table on Fz in [0, 8000] N with linear interpolation, built once at startup: at 1 kHz x 4 wheels that is 4000 evaluations/s of two sin/atan/exp chains, which is the single hottest path in the sim.
  def relax_step(k: float, Vs: float, Vx: float, sigma: float, dt: float) -> float
      Exact exponential update of one transient slip state: a = -|Vx|/sigma, c = Vs/sigma; returns k*exp(a*dt) + (c/a)*(exp(a*dt)-1), falling back to k + c*dt when |a*dt| < 1e-6. Unconditionally stable, exact for constant Vs, and finite at Vx = 0. This function is the entire answer to the V->0 singularity.
  def wheel_step(omega: float, I_eff: float, T_drive: float, T_brake: float, Fx_tyre: float, kv: float, Vx: float, r_roll: float, dt: float) -> tuple[float, bool]
      Implicit-in-omega wheel spin update including the Besselink damper on the left-hand side. Returns (omega_new, locked). The damper term kv*r^2/I_eff reaches 2299 s^-1 at standstill -- 2.3 e-foldings per millisecond -- so an explicit treatment of this one term alone would blow up at 1 kHz.
  def check_guards(state: VehicleState, cfg: SimConfig) -> GuardVerdict   # OK | CLAMPED | RESET
      NaN/Inf scan over all 26 scalars, then magnitude checks (|a| <= 40 m/s^2, |omega| <= 400 rad/s, |r| <= 6 rad/s, |v| <= 40 m/s, |phi| <= 0.6 rad, Fz sum within 0.5x-3x of m*g). CLAMPED clamps and logs; RESET restores the last known-good state (a ring buffer of 100 states = 0.1 s) or, if that is also bad, a fresh state at the last valid pose with zero velocity. Must log the first offending field name -- 'omega[1] became NaN at t=12.34' is a debuggable message, 'sim reset' is not.
  def virtual_driver_ramp_steer(V: float, rate_deg_s: float = 2.2, T: float = 16.0) -> RampResult   # peak_ay, delta_at_peak, util_f, util_r, beta
      THE quantitative grip-limit test driver. Speed is held exactly (longitudinal DOF frozen), road-wheel steer ramps linearly from 0, peak a_y is recorded. Deterministic, controller-free, no gains to tune. Aborts on |beta| > 12 deg and reports why. Every corner-speed and wing-delta number in the validation suite comes from this, bisected on V.
  def virtual_driver_pure_pursuit(R: float, V: float, Ld0: float = 6.0, kLd: float = 0.55, Ki: float = 0.10, T: float = 45.0) -> SkidpadResult   # max_radius_error, mean_ay, mean_delta, mean_beta
      Closed-loop constant-radius driver. Lookahead point at arclength Ld = Ld0 + kLd*u along the circle; delta = atan2(2*L*ly, Ld^2) + Ki*(integral of radius error)*L/R, clamped to +-35 deg. This is a DRIVABILITY test only: measured today, it saturates at 0.757 g on R=100 m while the car itself does 0.855 g, because the pure-pursuit geometry runs out of authority before the tyres do.
  def virtual_driver_straight(target: str, pedal: float) -> LongResult   # distance, time, peak_ax, min_kappa, gear_trace
      Open-loop longitudinal driver for the acceleration and braking tests. target in {'accel_0_100', 'vmax', 'brake_100_0'}. Steer held at 0, no stabilising feedback -- a straight-line test that needs steering correction is telling you the model is asymmetric, which is itself a bug worth surfacing.
  def replay(states: list[VehicleState], inputs: list[DriverInput]) -> bool
      Determinism check. Re-runs a recorded input sequence and asserts bit-identical states. Required because the validation suite is worthless if the sim is not reproducible: no wall-clock in the physics, no unordered dict iteration over wheels, no float accumulation of t (use t = n_steps * dt).

PITFALLS:
  - SIGN ASYMMETRY IN THE COMBINED-SLIP PROJECTION. Fx = +(sx/rho)*f*mu_x*Fz but Fy = -(sy/rho)*f*mu_y*Fz. I hit this in the prototype: with both signs negative the braking test produced 767 m and 0.031 g instead of 41.9 m and 0.99 g. Symptom: the car accelerates gently when you brake and the wheels never lock. The convention is kappa > 0 means the tyre drives the car FORWARD (+x), alpha > 0 means the tyre pushes the car to -y.
  - WHEEL ODE SIGN. Iw*domega/dt = T_drive - T_brake*sgn(omega) - r*Fx, where Fx is the force on the CAR. Writing +r*Fx (the intuitive 'the ground pushes the wheel round') spins the wheels UP under braking and DOWN under power. Test: apply brake with the engine off from 25 m/s and check that omega decreases.
  - INTEGRATION ORDERING IS THE WHOLE MODULE. The transient slip states must be advanced from the CURRENT omega, then the force computed from the NEW slip states, then omega advanced from that force. Reversing it (force from the old kappa, omega, then kappa from the old omega) diverges at every dt from 0.5 ms upward at V = 3 m/s -- measured. Symptom: at low speed the wheels start buzzing and the car shudders forward, worse the slower you go. If a code reviewer 'tidies up' the step function by hoisting the force calculation, this comes back.
  - NEVER FORM kappa = Vsx/Vx OR alpha = atan(Vy/Vx). Integrate sigma*dk/dt = -|Vx|*k + Vs instead: Vx appears only as a multiplier, so Vx = 0 is a regular point, not a singularity. This one change removes the low-speed blow-up, the reverse-gear atan2 breakage AND gives correct hill-holding for free (at Vx = 0 the state winds up like a spring of rate C_long = 381913 N/m per wheel). Do not 'fix' the singularity with max(V, 1.0) in a denominator -- that makes the tyre 10x too soft at 0.1 m/s and the car will creep away from a stop with the brakes on.
  - THE cos(delta) PROJECTION IS WHY THE SIM WILL NOT EXACTLY MATCH qss. qss.py resolves the front axle's required force in the body frame but takes the tyre capacity in the tyre frame, i.e. it implicitly assumes cos(delta) = 1. At the limit delta is 7.2 deg, so cos(delta) = 0.9921 and the sim reads 0.8545 g against qss's 0.862467 g. Verified: forcing cos(delta) = 1 recovers 0.8614 g, -0.13%. If your sim matches qss EXACTLY, you have forgotten the projection -- which also means you have forgotten the induced longitudinal force -Fy*sin(delta) that provides the front-tyre scrub drag qss models separately as m*a_y*sin(alpha_peak).
  - LOAD TRANSFER MUST USE qss's LUMPED FORM. dFz = (m*a_y*h_cg - F_w*h_w)/t_bar with t_bar = 1.42450 m (the MEAN track) split 0.74/0.26. A 'more physical' formulation -- per-axle tracks, sprung/unsprung decomposition, a roll-stiffness-derived split -- will miss test T5 by ~1% and cascade into a 0.5% corner-speed error that you will then chase for a day. roll_dist_f = 0.74 is a calibrated lumped parameter, not a derived one; treat it as data.
  - REFLECTED ENGINE INERTIA DOMINATES FIRST GEAR. Ie*n^2 = 0.12*13.967^2 = 23.41 kg m^2 = 292 kg of equivalent mass in 1st (+28.9%), 107 kg in 2nd, 18.5 kg in 5th. Omitting it makes 0-100 read 14.43 s instead of 16.17 s and, far worse, makes 1st gear feel unrealistically eager to the driver -- which is exactly the kind of thing a driving sim is FOR. Also remember it must vanish when the clutch is disengaged, or the car will feel like it has a flywheel bolted to the wheels during shifts.
  - sigma_x AND sigma_y MUST BE CLAMPED. K_xk(Fz) -> 0 as Fz -> 0, so sigma_x -> 0 for an unloaded inner wheel and the relaxation rate |Vx|/sigma -> infinity. With the exponential update this is harmless (exp(-inf) = 0, the state snaps to steady state), but with any forward-Euler update it is an instant NaN. Clamp sigma_x to [0.05, 0.40] m and sigma_y to [0.10, 0.50] m anyway -- at the cornering limit the front inner wheel carries 580 N and it WILL hit the floor.
  - Fz GOES NEAR ZERO ON THE INNER FRONT WHEEL. At the 0.862467 g limit the corner loads are 5463.5 / 580.4 / 2789.9 / 1074.2 N. Clamp Fz >= 0 before the tyre call, and make tyre_forces return exactly (0.0, 0.0) at Fz = 0 rather than dividing by mu*Fz somewhere. With the sealed plate at the front bumper the inner front actually lifts.
  - THE WING SIDE-SELECTION MUST BE tanh, NOT sign. s_wing = tanh(ay_filt/1.0) with ay_filt a 0.15 s lag. sign(a_y) at 1 kHz on a straight road produces a 1 kHz square-wave lateral force of +/-124 N as a_y dithers around zero, which reads as a violent buzz through the steering and can excite the yaw mode. Test: drive straight at 30 m/s with the wing deployed and confirm |v| stays below 1e-3 m/s.
  - BRAKE TORQUE MUST VANISH SMOOTHLY AT omega = 0. Use T_brake*tanh(omega/1.0). With sgn(omega) a locked wheel chatters between +T_b and -T_b at 1 kHz, which injects a 1600 Nm square wave into the wheel and shows up as a rasp in the deceleration trace. Keep the hard lock latch as well (omega_new*omega_old < 0 and no drive torque -> omega = 0) with 0.5/1.5 rad/s hysteresis: the tanh handles the smoothness, the latch handles the exactness.
  - THE LOW-SPEED DAMPER MUST BE IMPLICIT ON omega, NOT ON THE BODY. kv*r^2/I_eff = 24495*0.0801/0.85 = 2308 s^-1 at standstill -- 2.3 e-foldings per millisecond. Explicit, this alone destroys the sim at 1 kHz. The implicit form is one line: omega = (omega + (dt/I)*(...))/(1 + dt*kv*r^2/I). On the body the same term is only 96.6 s^-1 and could be explicit, but make it implicit too for symmetry.
  - DO NOT MEASURE THE GRIP LIMIT WITH THE CLOSED-LOOP SKIDPAD. Measured today: the tuned pure-pursuit driver bisects to 27.25 m/s on R = 100 m (0.757 g) while a ramp steer on the same car reaches 28.96 m/s (0.855 g). The controller saturates 12% below the car. Every quantitative number in the validation suite must come from the open-loop ramp steer; the skidpad is only there to prove a human-shaped controller can hold the line at 90% of the limit. Conversely, if you loosen the skidpad's radius tolerance to make it reach the limit, it will report 31.1 m/s (+7% ABOVE qss) because it is quietly driving a 114 m circle.
  - TRANSIENT PEAK a_y IS NOT SUSTAINABLE a_y NEAR THE REAR LIMIT. With the sealed plate at the front bumper the sim reports +2.626% while qss reports +0.193%, because qss's bisection stops the instant util_r reaches 1.0 whereas the ramp steer records the a_y peak that occurs as the car snaps into oversteer. This is not a bug in either model; it is why T14 (CG mount, both axles slack) is the quantitative test and T15/T17 are assertion tests on util_r. Always report util_f and util_r alongside any wing gain.
  - THE a_y USED FOR LOAD TRANSFER IS A CIRCULAR DEPENDENCY. Use the previous step's value. At 1 kHz the lag costs less than 0.05% on the measured limit (verified: dt from 0.25 to 4 ms changes peak a_y by 0.015%). Do not iterate to convergence inside the step -- it triples the cost for nothing and destroys determinism if the iteration count varies.
  - FIXED TIMESTEP, ACCUMULATOR, AND A SPIRAL GUARD. Never drive the physics off the pygame frame time. Cap at 8 substeps per frame and discard the remainder; a 60 fps frame needs 16.7 substeps at 1 kHz, so budget for that -- if the render loop stalls for 200 ms you must drop 192 steps rather than try to catch up, or one hitch cascades into a permanent slow-motion state. Log dropped_steps so a slow renderer is visible rather than felt as 'the car got weird'.
  - THE 15.5 s 0-100 FIGURE IN THE BRIEF IS IN TENSION WITH THE 170 km/h FIGURE. The top-speed balance pins P_wheel = 47.3 kW; with 1010 kg, that same power gives an ideal-CVT floor of 10.41 s and a realistic manual figure of 14.4-16.2 s depending entirely on Ie and the launch model. Opel's published figure for the Z12XE is 14.4 s. The gap between 14.43 s (Ie = 0) and 16.17 s (Ie = 0.12) is ALL flywheel inertia, and 15.30 s (Ie = 0.06) is the value that reproduces the brief. Do not tune eta_drive or the torque curve to hit 15.5 s -- that breaks Vmax, which is the better-attested number. Tune Ie, and say so.
  - BRAKES AND DAMPERS ARE MARKED MISSING IN corsa_c.py FOR A REASON. Every brake and damper number here is a reconstruction: 1600/560 Nm from a plausible 236 mm disc and 200 mm drum at 100 bar, C_phi from zeta = 0.40. They are calibrated against 100-0 = 41.9 m and a 1.45 Hz roll mode, not measured. Put them in a separate BRAKES/DAMPERS block in the config with the band written next to each value, so that when someone finally finds a workshop manual they change one file, not fifteen call sites.
