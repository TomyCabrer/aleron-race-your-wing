##### CHASSIS #####
SUMMARY:
A 26-state, 3-DOF-planar + 1-DOF-roll two-track model whose steady state reproduces qss.py. I prototyped the whole EOM in the scratchpad and solved its steady constant-radius equilibrium against qss.corner_speed: it lands at 28.941 m/s at R=100 m (qss 29.0875, -0.50%) and 20.431 m/s at R=50 m (qss 20.5679, -0.67%), front-limited (util_f 0.995 vs util_r 0.942) with roll_dist_f=0.74, roll 4.55 deg, per-corner Fz [607, 5437, 1084, 2780] N summing exactly to m*g. The residual -0.5% is NOT a bug: qss.axle_capacity sums each tyre's own peak Fy, i.e. it puts both tyres of an axle at their individual peak slip angles simultaneously (8.4 deg at 600 N, 11.6 deg at 5400 N), which is geometrically impossible when both wheels share one slip angle. The two-track answer is the right one and qss is 0.5-0.9% optimistic. Three real disagreements with qss.py are called out below with numbers, one of them a genuine algebra bug in qss.residuals (Y_r violates qss's own stated force balance by 2.3% whenever the wing is on, which is why qss's sealed-plate/front-axle number at R=100 is non-monotonic and LOWER than its own clean-fin number — the rear goes spuriously limiting). Key structural results: the (x_w+b)/b multiplier emerges from the yaw balance and matches crossover.gain to 0.07% for the clean fin; qss's lumped scrub drag m*a_y*sin(7deg) is exactly the -m*v*r Coriolis term plus the Y_f*sin(delta) steer resolution, which the time-domain model produces automatically (662 + 584 = 1246 N vs qss's 1031 N at R=100); and the load transfer is made fully explicit (no algebraic loop) by carrying dFz as lagged states. Dampers, brakes, tyre relaxation lengths, wheel inertia and compliance steer are unpublished — each is estimated below with a derivation, a band, and a named cross-check.

EQUATIONS:
  FRAME (lock this first, everything else depends on it): ISO body frame, x forward, y LEFT, z up. yaw psi and yaw rate r positive counter-clockwise seen from above = LEFT turn. a_y positive = leftward = toward the centre of a left turn. roll phi positive about +x by the right-hand rule = LEFT side rises = body rolls to the RIGHT = the outside of a left turn. In a left turn: r>0, a_y>0, phi>0, and at the limit v<0 and beta<0.
  STATE (26): s = [X, Y, psi, u, v, r, phi, p, w_fl, w_fr, w_rl, w_rr, a_fl, a_fr, a_rl, a_rr, k_fl, k_fr, k_rl, k_rr, dFz_f, dFz_r, dFz_x, dsw, dsw_dot, dep]  where a_* are RELAXED slip angles (rad), k_* relaxed slip ratios (-), dFz_* lagged load transfers (N), dsw filtered steering-wheel angle (rad), dep device deployment fraction 0..1. Non-state auxiliaries: gear index (int), dev_side (+1/-1, hysteretic).
  --- STEP 1: STEERING ---
  dsw_cmd = key_axis * dsw_lim(u);   key_axis in [-1,+1] from the keyboard integrator
  dsw_lim(u) = min( dsw_lock , steer_ratio * a_y_cap * ( L/max(u,u_lo)^2 + K_us/g ) )   with dsw_lock = 9.1106 rad (522 deg), a_y_cap = 9.5 m/s^2, K_us = 0.0391 rad/g, u_lo = 1.0 m/s
  dsw_ddot = ws^2 * (dsw_cmd - dsw) - 2*zs*ws*dsw_dot,   ws = 15.71 rad/s (2.5 Hz), zs = 1.0
  dsw_dot := clamp(dsw_dot, -sw_rate, +sw_rate);   sw_rate = 12.22 rad/s (700 deg/s) when |dsw_cmd| > |dsw|, 15.71 rad/s (900 deg/s) on return to centre
  delta_bic = dsw / steer_ratio                                  (steer_ratio = 16.0)
  ACKERMANN: if |delta_bic| > 1e-4: Rt = L / tan(delta_bic); di_full = atan(L/(Rt - sgn*t_f/2)); do_full = atan(L/(Rt + sgn*t_f/2)) with sgn = sign(delta_bic); else di_full = do_full = delta_bic
  delta_in  = delta_bic + A_ack*(di_full - delta_bic);  delta_out = delta_bic + A_ack*(do_full - delta_bic);   A_ack = 0.60
  assign: for a LEFT turn (delta_bic>0) the INNER wheel is FL, so delta_FL = delta_in, delta_FR = delta_out; mirrored for a right turn
  COMPLIANCE STEER (this is what sets the linear-range understeer; tyres alone give only 0.37 deg/g): delta_FL -= eps_f * Fy_f_prev ; delta_FR -= eps_f * Fy_f_prev   with Fy_f_prev = Fy_body_FL + Fy_body_FR from the previous substep, eps_f = 5.40e-6 rad/N
  delta_RL = delta_RR = -c_rs * phi        with c_rs = 0.0 by DEFAULT (see pitfalls; corsa_c.rollsteer_r = 1.0 deg/deg is wrong in sign and magnitude)
  --- STEP 2: PER-CORNER NORMAL LOADS (all algebraic, all from states -> no fixed-point iteration needed) ---
  Fz_f_static = m*g*wdist_f/2 ;  Fz_r_static = m*g*(1-wdist_f)/2
  Fz_FL = max( Fz_f_static - dFz_x/2 - dFz_f , 0 )
  Fz_FR = max( Fz_f_static - dFz_x/2 + dFz_f , 0 )
  Fz_RL = max( Fz_r_static + dFz_x/2 - dFz_r , 0 )
  Fz_RR = max( Fz_r_static + dFz_x/2 + dFz_r , 0 )
  (sign: dFz_f, dFz_r > 0 transfer load to the RIGHT wheels = the outside of a LEFT turn; dFz_x > 0 transfers load to the REAR = forward acceleration)
  --- STEP 3: TYRE KINEMATICS, per corner i at body position (x_i, y_i): FL(+a,+t_f/2) FR(+a,-t_f/2) RL(-b,+t_r/2) RR(-b,-t_r/2) ---
  vx_i = u - r*y_i ;   vy_i = v + r*x_i
  vlon_i =  vx_i*cos(delta_i) + vy_i*sin(delta_i)
  vlat_i = -vx_i*sin(delta_i) + vy_i*cos(delta_i)
  alpha_i = atan2( vlat_i , max(|vlon_i|, v_low) )        v_low = 1.0 m/s  (matches VXLOW in the .tir files)
  kappa_i = ( w_i*R_e - vlon_i ) / max(|vlon_i|, v_low)
  sigma_y_i = clamp( C_alpha(Fz_i) / K_carc_y , 0.20 , 0.80 )   K_carc_y = 110e3 N/m
  da_i/dt = ( max(|vlon_i|, v_low) / sigma_y_i ) * ( alpha_i - a_i )        [relaxed slip angle]
  dk_i/dt = ( max(|vlon_i|, v_low) / sigma_x   ) * ( kappa_i - k_i )        sigma_x = 0.25 m
  --- STEP 4: TYRE FORCES (wheel frame) — from the tyre module, called with the RELAXED slips ---
  Fx_i, Fy_i = tyre(a_i, k_i, Fz_i, mu_scale)      Fy_i must satisfy: peak|Fy_i|(k=0) == mu(Fz_i)*Fz_i with mu(Fz) = 0.903 - 16.1e-6*(Fz - 2477), i.e. IDENTICAL to qss.TYRE, or the acceptance tests below will not close
  Fxb_i = Fx_i*cos(delta_i) - Fy_i*sin(delta_i)         [rotate wheel -> body]
  Fyb_i = Fx_i*sin(delta_i) + Fy_i*cos(delta_i)
  --- STEP 5: AERO ---
  q = 0.5*rho*V^2   with V = sqrt(u^2 + v^2), rho = 1.2
  beta = atan2(v, max(u, v_low))
  BASE DRAG:  D_aero = q * CdA                                     CdA = 0.66, applied at h_aero = h_cg (so it makes no pitch moment; the error at Vmax is 35 N of dFz_x, 0.4%)
  BODY SIDE FORCE (default ON in drive mode, forced OFF in qss-parity mode):  Fy_body = -q * A * Cs_psi * beta ;  Mz_body = Fy_body * x_cp     A = 2.01, Cs_psi = 2.2 /rad, x_cp = +0.30 m. (beta<0 in a left turn -> Fy_body>0 = inward, i.e. it HELPS; its yaw moment ahead of the CG is destabilising, as it should be.)
  FLANK WING — side selection: sgn_dev = +1 if the car is being turned LEFT, -1 if right. Take sgn_dev from sign(dsw) with a deadband of 0.05*dsw_lock and 0.3 s hold, NOT from sign(v) and NOT from sign(beta).
  deployment actuator:  d(dep)/dt = clamp( (dep_cmd - dep)/tau_dev , -1/t_ret , +1/t_ext )   tau_dev = 0.25 s, t_ext = 0.45 s, t_ret = 0.30 s; forbid a change of sgn_dev while dep > 0.05
  device incidence:  alpha_dev = delta_dev_geom + sgn_dev * (-beta)    [in a LEFT turn sgn_dev=+1 and beta<0, so the body slip ADDS incidence — that is the free bonus, and it is why the sign of beta must never be used to pick the side]
  CL_dev = clamp( CL0 + dCLda * alpha_dev , 0 , CL_stall )      dCLda = 2.47 /rad, CL_stall = 1.6; set dCLda = 0 and CL_dev = CL0 to run in exact qss/crossover/ledger parity mode
  F_dev = sgn_dev * dep * q * S_DEV * CL_dev            [+y = inward for a left turn]  S_DEV = 0.35 m^2 (ONE panel; only one panel is active at a time)
  D_dev = dep * q * S_DEV * CL_dev / LD_dev             [always along -x]  LD_dev = 3.2
  Mz_dev = F_dev * x_w  -  D_dev * y_dev * sgn_dev      y_dev = -sgn_dev * 0.72 m (the OUTER flank); the drag term is ~50 Nm against ~215 Nm from the side force, include it for completeness
  --- STEP 6: FORCE AND MOMENT SUMS ---
  SFx = sum(Fxb_i) - D_aero - D_dev
  SFy_tyre = sum(Fyb_i)
  SFy = SFy_tyre + F_dev + Fy_body
  SMz = sum( x_i*Fyb_i - y_i*Fxb_i ) + Mz_dev + Mz_body        [the -y_i*Fxb_i term is how asymmetric drive/brake force makes yaw — do not drop it]
  --- STEP 7: COUPLED LATERAL + ROLL (solve the 2x2 exactly, do not decouple) ---
  Mx_ext = m_s*g*h_r*sin(phi) - Kphi*phi - Cphi*p - F_dev*(h_w - h_ra)      [this reproduces qss.roll_angle term for term]
  [ m        -m_s*h_r ] [ a_y ]   [ SFy    ]
  [ -m_s*h_r  I_roll  ] [ pdot ] = [ Mx_ext ]
  det = m*I_roll - (m_s*h_r)^2 = 225219  (well conditioned)
  a_y  = (  I_roll*SFy + m_s*h_r*Mx_ext ) / det
  pdot = ( m_s*h_r*SFy + m*Mx_ext      ) / det
  --- STEP 8: RIGID-BODY DERIVATIVES (the Coriolis terms a naive model omits are the +u*r and -v*r) ---
  dX/dt   = u*cos(psi) - v*sin(psi)
  dY/dt   = u*sin(psi) + v*cos(psi)
  dpsi/dt = r
  du/dt   = SFx/m + v*r                       <-- +v*r, NOT SFx/m alone
  dv/dt   = a_y   - u*r                       <-- a_y is (vdot + u*r) from step 7, so dv/dt = a_y - u*r
  dr/dt   = SMz / Izz
  dphi/dt = p
  dp/dt   = pdot   (from step 7)
  --- STEP 9: LOAD-TRANSFER STATES (this is what makes the whole step explicit: dFz are states, so Fz does not depend on the Fy computed this step) ---
  dFz_tot_demand = ( SFy_tyre*h_cg + F_dev*(h_cg - h_w) ) / t        [ALGEBRAICALLY IDENTICAL to qss's (m*a_y*h_cg - F*h_w)/t, because m*a_y = SFy_tyre + F_dev + Fy_body; the Fy_body term is the only difference and is 175 N at the limit]
  dFz_x_demand   = ( sum(Fxb_i) * h_cg ) / L                          [drag omitted: it acts at h_aero = h_cg and cancels]
  RECOMMENDED (two-rate, gets the instantaneous geometric split right): let LT = LPF(dFz_tot_demand, tau_roll) with tau_roll = 0.09 s. Then
    ddFz_f/dt = ( 0.101*dFz_tot_demand + 0.639*LT - dFz_f ) / tau_LT
    ddFz_r/dt = ( 0.221*dFz_tot_demand + 0.039*LT - dFz_r ) / tau_LT       tau_LT = 0.02 s
    (steady state: 0.101+0.639 = 0.740 front, 0.221+0.039 = 0.260 rear == roll_dist_f exactly. At t=0+ only the geometric+unsprung part is present, split 0.101/0.221 = 31/69 front/rear, so the car is momentarily loose at turn-in and settles into understeer as roll builds — the real behaviour of a high-rear-roll-centre torsion beam.)
  SIMPLE FALLBACK (use if the two-rate form is not wanted): ddFz_f/dt = (0.74*dFz_tot_demand - dFz_f)/tau_LT ; ddFz_r/dt = (0.26*dFz_tot_demand - dFz_r)/tau_LT with tau_LT = 0.06 s. Same steady state, no turn-in nuance.
  ddFz_x/dt = ( dFz_x_demand - dFz_x ) / tau_pitch      tau_pitch = 0.12 s
  --- STEP 10: WHEEL SPIN ---
  I_eff_i = I_w + (i is a FRONT wheel ? I_driveline * (gear[g]*finaldrive)^2 / 2 : 0)      I_w = 0.65, I_driveline = 0.12 kg m^2
  dw_i/dt = ( T_drive_i - T_brake_i*tanh(w_i/w_eps) - Fx_i*R_e - Crr*Fz_i*R_e ) / I_eff_i    w_eps = 1.0 rad/s, R_e = r_roll = 0.283 m
  --- STEP 11: INTEGRATION ---
  Semi-implicit (symplectic) Euler at dt_phys = 1/1000 s, sub-stepped inside the render frame (17 substeps at 60 Hz). Order within a substep: integrate the tyre relaxation and wheel-spin states first (they are the stiff ones), then the rigid-body states, then the load-transfer and steering states. Do NOT use RK4: the tanh brake term and the Fz clamp are non-smooth and RK4 buys nothing here.
  --- DIAGNOSTIC IDENTITIES the sim should expose (for the HUD and the tests) ---
  util_f = |Fyb_FL + Fyb_FR| / ( |Fy_peak(Fz_FL)| + |Fy_peak(Fz_FR)| )    ;  util_r likewise
  Y_f_expected = ( b*m*a_y - F_dev*(b + x_w) ) / L        <-- the (x_w+b)/b multiplier; assert against the model's own Fyb_FL+Fyb_FR
  P_wheel_required = V * ( -m*v*r + Y_f*sin(delta_bic) + D_aero + D_dev + Crr*m*g )   <-- this IS qss's scrub-drag term, emergent

CRITICAL: referred to each front wheel this is I_drv*(gear*FD)^2/2 = 12.36 kg m^2 in 1st, 4.93 in 2nd, 1.39 in 5th -- 19x the wheel's own inertia in 1st. Omit it and 1st gear will feel weightless and the car will spin its wheels wrongly. It is a powertrain-module input; vehicle.py must accept it, not hard-code it.
  R_e (effective rolling radius) = 0.283 [m] (published) :: corsa_c.r_roll (OD 583.1 mm x 0.97). Treat as constant; load-dependent R_e buys nothing here.
  CdA / rho / Crr = 0.66 / 1.2 / 0.012 [m^2 / kg m^-3 / -] (published) :: corsa_c. Cross-check PASSES: at Vmax 47.2 m/s the required wheel power is 47.253 kW against P_wheel = eta*P_max = 47.300 kW, a 0.10% miss.
  h_aero (drag application height) = 0.55 (= h_cg) [m] (estimated) :: Chosen so drag makes no pitch moment. Justification: even a 0.10 m error changes dFz_x at Vmax by only 35 N (0.4% of the front axle load).
  Cs_psi / A / x_cp (body side force) = 2.2 /rad / 2.01 m^2 / +0.30 m [-/rad, m^2, m] (estimated) :: Cs_psi from ledger.py's default (swept there over 1.0-3.0, unmeasured, no CFD). x_cp = +0.30 m is an estimate; a hatchback's aerodynamic centre of pressure sits ahead of the CG, which is why cars are yaw-unstable in a crosswind. At the R=100 limit this gives 175 N of inward force (4% of the cornering force) and 52 Nm of destabilising yaw moment. DEFAULT ON in drive mode, forced OFF in qss-parity mode.
  S_DEV = 0.35 [m^2] (published) :: ledger.S_DEV, per side. ONE panel active at a time: crossover/ledger/qss all use k = 0.5*rho*S_DEV*CL with the one-side area, so the sim must not deploy both panels and double the force.
  CL0 (clean fin / sealed plate) = 0.70 / 1.25 [-] (estimated) :: crossover.q3_gain, ledger.sweep
  dCLda (device lift-curve slope) = 2.47 /rad = 0.0431 /deg [1/rad] (derived) :: DERIVED: 2*pi*AR/(AR+2) at AR = 1.3 (the AR crossover.py cites for the L/D 3.2 figure). Set to 0 to run exact qss/crossover parity. CL_stall = 1.6, band 1.4-1.8 for a low-AR endplated surface.
  LD_dev = 3.2 [-] (estimated) :: qss.corner_speed / ledger, 'AR 1.2-1.4 fin'
  x_w (mount station) = crossover.MOUNTS: front bumper +1.74, front axle +0.97, mid front door +0.40, at the CG 0.00, rear axle -1.52 [m, positive FORWARD of the CG] (published) :: crossover.MOUNTS
  h_w (mount height) = 0.70 recommended (qss default 0.90) [m] (estimated) :: A flank panel spans sill (~0.35 m) to shoulder line (~1.05 m) -> centre of pressure ~0.70 m. Band 0.55-0.95. IT BARELY MATTERS for corner speed: sweeping h_w from 0.30 to 1.10 m moves the R=100 sealed-plate gain only from +2.23% to +2.39%. It matters for ROLL, which the driver feels: at 222 N and h_w=0.90 it removes 0.257 deg from a 4.55 deg roll (5.6%). Use 0.90 for the acceptance tests so they match qss defaults.
  y_dev (device lateral station, for its drag's yaw moment) = 0.72 (on the outer flank, so y_dev = -sgn_dev*0.72) [m] (derived) :: half the mean track
  dt_phys = 0.001 [s] (derived) :: Set by the wheel-spin mode: tau = I_eff*u/(C_kappa*R_e^2) ~ 4.9 ms at 30 m/s with I_w alone, and much stiffer at low speed. 1 ms with semi-implicit Euler is safe; 17 substeps per 60 Hz frame is ~5 microseconds of work in pure Python per corner.
  v_low = 1.0 [m/s] (published) :: VXLOW in every .tir file in tyre_data/. Use it as the divisor floor in slip angle, slip ratio and relaxation rate.

    """[(x_i, y_i)] in the ISO body frame, order FL FR RL RR, y positive LEFT.

  def steer_limit(u: float, car, cp: ChassisParams) -> float:

  def normal_loads(st: VehicleState, car) -> list[float]:
    """Per-corner Fz in N, order FL FR RL RR, each clamped at 0.
    Purely a function of the dFz_f/dFz_r/dFz_x STATES -- no iteration, no
    dependence on this step's tyre forces."""

  def aero(st: VehicleState, car, cp: ChassisParams, dev: DeviceParams) -> dict:
    """Returns {'Fx': N (negative = drag), 'Fy': N (+left), 'Mz': Nm,
               'F_dev': N (+left), 'D_dev': N, 'CL_dev': -, 'alpha_dev': rad,
               'beta': rad, 'q': Pa}.

  def derivatives(st: VehicleState, ctl: Controls, drive: DriveInputs, car,
                cp: ChassisParams, dev: DeviceParams, tyre, mu_scale: float = 1.0)
                -> tuple[np.ndarray, dict]:
    """Full state derivative plus a diagnostics dict.
    drive carries per-wheel T_drive (Nm), T_brake (Nm) and I_referred (kg m^2)
    from the powertrain/brake modules -- vehicle.py never computes engine torque.
    diagnostics: a_y, a_x, Fz[4], alpha[4], kappa[4], Fx[4], Fy[4],
                 util_f, util_r, dFz_tot_demand, beta, P_wheel_required,
                 Y_f_expected, wheel_lift[4], limiting_axle."""
      The one entry point. It must be side-effect free so the acceptance tests can call it at a constructed state. The diagnostics dict is not optional -- every acceptance test below reads it.
  def step(st: VehicleState, ctl: Controls, drive: DriveInputs, dt: float, *,
         car, cp, dev, tyre, mu_scale=1.0, substeps: int = 17) -> tuple[VehicleState, dict]:
    """Advance one render frame by semi-implicit Euler with `substeps` inner
    steps of dt/substeps. Integration order inside a substep:
    (1) alpha_r, kappa_r  (2) w  (3) u,v,r,phi,p  (4) X,Y,psi
    (5) dFz_f,dFz_r,dFz_x  (6) dsw,dsw_dot,dep."""
      Returns the diagnostics of the LAST substep for the HUD. substeps=17 at 60 Hz gives dt_phys = 0.98 ms.
  def steady_state_corner(R: float, *, car, cp, dev, tyre, mu_scale=1.0,
                        power_cap: bool = False, combined_slip: bool = False,
                        tol: float = 1e-6) -> dict:
    """Solve the EOM's own steady constant-radius equilibrium at radius R by
    bisecting on V and, at each V, solving the 2-equation residual
    [lateral balance, yaw balance] for (delta_bic, beta) with the load-transfer
    states set to their fixed points.  Returns
    {'V', 'ay_g', 'beta_deg', 'delta_deg', 'alpha_f_deg', 'alpha_r_deg',
     'util_f', 'util_r', 'limiting', 'Fz', 'dFz_tot', 'phi_deg',
     'coriolis_N', 'induced_N', 'P_required_kW'}."""
      THIS is the function the acceptance tests call. It is not part of the real-time loop but it must use the SAME force/moment/load-transfer code as derivatives() -- share the internals or the tests validate nothing. power_cap=False means grip-only, matching qss.corner_speed(power_cap=False).
  def validate(verbose: bool = True) -> bool:

    Must be callable as `python -m drive.vehicle` and must exit non-zero on
    any failure."""
      Non-negotiable. This is how anyone later touching the load-transfer signs finds out immediately.

PITFALLS:
  - BUG IN qss.py — Y_r violates qss's own force balance. qss.residuals line 88 has Y_r = (a*m*a_y + F*x_w)/L. Solving qss's own two stated equations (Y_f + Y_r + F = m*a_y and Y_f*a - Y_r*b + F*x_w = 0) gives Y_r = (a*m*a_y - F*(a - x_w))/L. The shipped code is missing -F*a/L. Check: Y_f + Y_r as coded = m*a_y - F*b/L, not m*a_y - F. Magnitude at F = 200 N: Y_r 3410.6 N coded vs 3332.6 N correct, +2.34%, and the sum misses m*a_y - F by exactly 78 N. Y_f is correct, so with the wing OFF (F = 0) the two agree exactly and every baseline number in qss stands. With the wing ON the inflated Y_r makes the rear go spuriously limiting: qss reports the sealed plate at the front axle giving +1.18% at R=100, LOWER than its own clean fin's +1.21% — physically impossible for a front-limited car. Patch qss's Y_r and it becomes +2.20%, matching this EOM's +2.35%. THE EOM IS RIGHT; qss is wrong here. My model never has this bug because it sums real per-wheel forces instead of imposing an axle split. Tell the qss author.
  - The EOM cannot and must not reproduce qss's corner speeds exactly. qss.axle_capacity sums fy_max(Fz_outer) + fy_max(Fz_inner), i.e. it puts both tyres of an axle at their own individual peak slip angles at the same instant. Both wheels on an axle share (to within Ackermann and track-speed effects) one slip angle, and the peak slip angle rises with load — 8.4 deg at 600 N, 9.0 deg at 2477 N, 11.6 deg at 5400 N. So one of the pair is always off-peak. The cost is -0.47% to -0.94% depending on radius. If your two-track model matches qss to better than 0.1%, or beats it, you have accidentally reimplemented axle_capacity somewhere. Bake the inequality V_eom <= V_qss into the test.
  - SIGN OF THE DEVICE FORCE — pick the side from the STEERING COMMAND, never from beta or v. In a left turn at the limit, beta is NEGATIVE (-4.5 deg) because the nose points inside the velocity vector. A naive sgn_dev = sign(beta) therefore deploys the panel on the WRONG side at exactly the moment it matters, and gives -2.14% instead of +2.35%. Worse, beta changes sign near the apex on a trailing-throttle entry, so the panel would chatter. Use sign(dsw) with a 5% deadband and a 0.3 s hold. Acceptance: the gain must be positive at every mount and every radius; if you see a loss, the sign is flipped.
  - DOUBLE-COUNTING THE DEVICE IN THE LOAD TRANSFER — I made this exact error in my own prototype and it took a mount-height sweep to catch it. qss's dFz_tot = (m*a_y*h_cg - F*h_w)/t. When you rewrite it in terms of forces (which you must, to break the algebraic loop) the substitution is m*a_y = SFy_tyre + F_dev, so dFz_tot = (SFy_tyre*h_cg + F_dev*(h_cg - h_w))/t. If your SFy_tyre already includes F_dev you get F_dev*(2*h_cg - h_w) and the h_w sensitivity comes out wrong. Symptom: the mount-height sweep (T13) moves by much more than 0.35 percentage points, and the h_w = 0 case does not leave the load transfer at m*a_y*h_cg/t.
  - THE FRAME-INDEPENDENCE ARGUMENT (qss.roll_angle's docstring is correct and worth restating because it is the reason the model is simple). Take moments in the y-z plane about the OUTER contact line, at ground level, using only external forces: weight -W at t/2 inboard, inner normal N_in at t inboard, outer normal at the pivot (no arm), the total tyre lateral force at z = 0 (no arm), the device force F at height h_w, and the d'Alembert force m*a_y at h_cg. Result: N_in = W/2 + (F*h_w - m*a_y*h_cg)/t, i.e. dFz_tot = (m*a_y*h_cg - F*h_w)/t. No roll axis, no spring rate, no sprung/unsprung split appears anywhere — the TOTAL transfer is a ground-plane statement and is frame independent. The roll axis sets only (a) the front/rear SPLIT of that total and (b) the roll ANGLE. Do not try to build the total out of spring forces; you will get it wrong and it will not match qss.
  - roll_dist_f = 0.74 IS NOT REACHABLE FROM THIS CAR'S PUBLISHED SUSPENSION GEOMETRY. Building the split properly — elastic (Kphi_f/Kphi_tot on m_s*a_y*(h_cg-h_ra)) plus geometric (m_s_axle*a_y*h_rc/t) plus unsprung — gives LLTD_f = 0.51 with the springs-only 311/195 ratio. Even assigning ALL the elastic roll stiffness to the front axle caps it at 0.726, because h_rc_r = 0.300 m makes the rear geometric transfer 622 N (19% of the 3300 N total) all by itself. So 0.74 is a calibration constant standing in for what neither model contains (front tyres also carrying tractive force, front tyres running deeper into slip, compliance). Keep it at 0.74 — qss's a_y = 0.8625 g, its 4.8% margin, crossover's sqrt(mu_r/mu_f) cap and ledger's entire verdict are all pinned to it — but expose it as a top-level tunable and never let anyone 'fix' it by deriving it from the roll centres.
  - corsa_c.rollsteer_r = 1.0 deg toe-out per deg roll IS WRONG and will destroy the car if implemented literally. At the limit the body rolls 4.55 deg, so this would command 4.55 deg of rear toe-out — the car would snap into instant oversteer and no acceptance test would pass. Torsion beams are deliberately designed to roll-UNDERsteer (bushing compliance toes the outer rear wheel IN). Default c_rs = 0.0. If enabled, use +0.06 deg/deg INTO the turn. This is the same term qss.residuals already disables with the comment 'this term as written does not model what it claims' — the sign problem is real and it is in corsa_c, not just in qss.
  - qss's SCRUB DRAG IS THE CORIOLIS TERM, and you get it for free if and only if you keep the u*r and v*r terms. m*(udot - v*r) = SFx with udot = 0 gives SFx = -m*v*r = m*a_y*|beta|. At the R=100 limit beta = -4.49 deg so -m*v*r = 662 N, and the front tyres' lateral force resolved through the steer angle adds Y_f*sin(delta) = 584 N, total 1246 N against qss's lumped m*a_y*sin(7 deg) = 1031 N. Do NOT add a separate 'scrub drag' term on top — you would be counting it twice. And note the structural difference: qss's version is linear in a_y with a fixed 7 deg, so it under-charges at the limit (by 21%) and over-charges below it. Below the limit qss is badly pessimistic: at R=250 qss says 36.44 m/s power-limited, the EOM says 40.40 m/s (+10.9%). The EOM is right; qss's power-limited radii are conservative.
  - THE ALGEBRAIC LOOP. Fz depends on the lateral force, the lateral force depends on Fz. Do not iterate it inside the frame, and do not use last frame's Fy raw. Make dFz_f, dFz_r and dFz_x STATES with the lags of step 9 and the whole derivative evaluation becomes explicit and single-pass. (For reference, if you do choose to iterate: the loop gain is (h_cg/t)*(mu_marg_outer - mu_marg_inner) = 0.386 * -0.065 = -0.025, so one Gauss-Seidel pass is already accurate to 2.5% of the correction and two are exact to 0.06%. But the lag version is both faster and more physical.)
  - STIFFNESS AT LOW SPEED. Slip ratio, slip angle and the relaxation rate all divide by longitudinal velocity. Use max(|vlon|, 1.0) everywhere — 1.0 m/s is VXLOW in every .tir in tyre_data/, so it is the tyre model's own documented floor. Separately, the wheel-spin mode has tau = I_eff*u/(C_kappa*R_e^2), about 4.9 ms at 30 m/s with the bare wheel inertia and far stiffer at low speed and in low gears. dt = 1 ms with semi-implicit Euler is the recommendation; explicit Euler at 60 Hz will explode on the first standing start.
  - FIRST-GEAR DRIVELINE INERTIA. Referred to each front wheel, I_drv*(gear*FD)^2/2 is 12.36 kg m^2 in 1st against the wheel's own 0.65 — a factor of 19. Omit it and the wheels will spin up instantly on any throttle input, the car will feel weightless off the line, and the 0-100 time will be nonsense. vehicle.py must accept I_referred per wheel from the powertrain module rather than assuming I_w.
  - tyre_data/mf_eval.py's file list points at a non-existent tir/ subdirectory, and it runs its whole report at import time. Do not `import mf_eval` — either fix the paths in a copy or exec only the function definitions (split the source at 'files=['). The 205/60R15 .tir files (TNO, TASS, Siemens) are byte-identical in every Fy0 parameter that matters; they are one dataset under three names, so averaging them is double-counting exactly as crossover.py warns. Also note they describe a 205/60R15 at FNOMIN 4000 N and UNLOADED_RADIUS 0.3135, not the car's 175/65R14 at r_roll 0.283: scale by Fz, never by radius.
  - THE TYRE MODEL MUST REPRODUCE qss's mu(Fz) EXACTLY or none of these numbers close. qss uses the linear fit mu = 0.903 - 16.1e-6*(Fz - 2477). The raw TNO .tir evaluated directly gives mu(2477) = 0.9233 and a local slope near -25e-6 per N — a 2% higher peak and a 55% steeper load sensitivity. Those are different tyres as far as the acceptance tests are concerned (a_y would come out about 0.88 g instead of 0.8625 g). Follow qss's fit for the validation path and expose the raw-.tir path as a separate, clearly-labelled option.
  - STEERING WITHOUT A FILTER MAKES THE CAR UNDRIVEABLE, and the fix must live in vehicle.py, not in the input layer. A raw keyboard axis is a step from 0 to full lock. At 30 m/s full lock (32.6 deg road wheel) commands roughly 40 g. Two things are needed together and neither alone is enough: (a) the speed-sensitive limit steer_limit(u), which returns full lock below 6.7 m/s and only 58.8 deg of steering wheel at 30 m/s, and (b) the critically damped 2.5 Hz second-order filter with a 700 deg/s rate limit. With only (a) the car still snaps; with only (b) it still asks for 40 g eventually.
  - LINEAR-RANGE UNDERSTEER IS NOT THE SAME KNOB AS LIMIT UNDERSTEER, and this model gets them from different places. Limit understeer comes from roll_dist_f = 0.74. Linear-range understeer comes from K_us = W_f/C_f - W_r/C_r, which from the TNO cornering stiffnesses alone is only 0.00645 rad = 0.37 deg/g, i.e. a characteristic speed of 61.6 m/s — nearly neutral and completely unlike a real Corsa (V_char 22-28 m/s). Without the eps_f compliance-steer term the car will feel darty and nervous on the straight while still understeering at the limit, which is exactly backwards. eps_f = 5.40e-6 rad/N fixes the linear range and provably does not touch any limit test (the steady-state solver just winds on 1.3 deg more lock).
  - S_DEV = 0.35 m^2 IS ONE PANEL, NOT TWO. crossover, ledger and qss all build k = 0.5*rho*S_DEV*CL from the one-side area, so the sim must deploy exactly one panel at a time. Deploying a mirrored pair would either double the force (wrong by 2x against every reference number) or cancel it entirely. The 39 kg mass penalty in ledger.py covers both panels plus the mechanism; that is a mass bookkeeping question, not an area question.
  - WHEEL LIFT AND VERTICAL EQUILIBRIUM. At the R=100 limit the inner front is already down to 607 N, so any kerb, trail-brake or quick flick will lift it. Clamp Fz at 0 and let that corner produce zero force — but do NOT redistribute the shortfall to the other wheels, because that would break the ground-plane moment balance that the whole load-transfer derivation rests on. The consequence is that sum(Fz) < m*g while a wheel is lifted; with no heave DOF that is the correct and standard behaviour, and the error is bounded by the clamp. Expose wheel_lift[i] so the HUD and the tests can see it, and make sure mu(Fz) is guarded at Fz -> 0 so it cannot go negative or divide by zero in B = C_alpha/(C*D).
