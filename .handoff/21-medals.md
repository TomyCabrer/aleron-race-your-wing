# Task 21 — medals, derived from laps that were driven

The brief (`PLAN-steam-engagement.md`, T21 and decision D4): a medal table
per class, generated by `python3 -m drive.medals --build`; the author time is
the best of the reference drivers run headless on the stock build; gold /
silver / bronze = author x 1.02 / 1.06 / 1.12; a class nobody laps has no
medals, not an invented time; the results show the medal earned, the best
per class is kept, the pre-race page shows the targets; the self-check covers
every class, the ordering and staleness.

## How a reference lap is driven

Exactly the way a player's lap is timed (`drive/medals.py`, `_drive`): the
class's STOCK car (`cars.get`, no wings, no ballast, the engine's
`power_scale`, the car's own grip), the class's track as a session builds it
(the standard 50 m skidpad; surfaces off only for 'none'; global wet for
'all'), 1 ms, a standing start on the line in 1st, timed by a `Sim` and its
`LapTimer`, the flying lap after the out-lap. A lap counts when the timer
calls it valid, it went ROUND (every sector line in order and 95 % of the
length -- a player record's own rule) and it has NO SPIN in it (|beta| < 35
deg throughout): a lap that stayed on the tarmac through a 180 would put gold
a spin away. A run stops at 2 valid flying laps, when the car is lost (off
the map or spun to a stop for 3 s, or under 30 m of progress in 12 s -- a car
spinning donuts) or at T_MAX.

The drivers: `LapDriver` at margins 0.90 / 0.80 / 0.70 / 0.60, the
`drive.ml` anchor (`Policy()`, theta = 0) and every bundled checkpoint whose
meta names the car and the map, driven the way `_ml_input` drives one; each
with the aids off and on. Author = the best lap of all of them. Every run's
result is kept in the class entry (`tried`), so a medal comes with its
evidence. Two classes whose physics is identical (the skidpad and the open
map have no patches to switch off: 'none' = 'patch') are driven once
(`ran_as`).

Who set the 81 author times: LapDriver 0.90 53, its careful margins 10
(0.80 x6, 0.70 x2, 0.60 x2), `arena_open_plate` 10, the anchor 6,
`540i_arena_plate` 2; with the aids on 50, off 31. Examples: arena / Corsa /
stock / wet patches 1:00.835 (gold 1:02.052); arena / Corsa / sport / patches
58.237 (`arena_open_plate`); skidpad / MX-5 / stock / patches 16.319.

## What changed from the first build, and why

The module was written and built by a subagent to the brief above
(LapDriver at 0.90 only, no spin rule): 78 of 81 lap classes had medals and
**five were far too easy** -- the only valid lap was one with a spin in it
(skidpad / MX-5 / sport / all-wet 43.296 s against the stock MX-5's 20.525;
tuned 39.261; Corsa sport all-wet 23.875) -- and three all-wet arena classes
had none. Measured, one class at a time: LapDriver at a lower margin laps
them cleanly -- the 2x MX-5 on the all-wet skidpad in 25.139 s at 0.60, the
2x Corsa in 21.476 s at 0.80, the 2x 540i on the all-wet arena in 78.32 s at
0.80. So the careful margins were added (the same scripted driver, only more
careful), and spun and short laps stopped counting. Rebuilt: **81 of 81**
lap classes have medals and none is a spun lap.

## What the review found

Two lenses (the build; the integration and the data), 2 finders and 7
verifiers. The verifiers refuted every claim as a defect under the brief's
scope, but five were worth doing anyway and are in this commit:

* a `--build --only TRACK` on a STALE table stamped it current with the other
  maps dropped (54 classes "not built yet") and the self-check passed -- now
  `--only` refuses on a stale table, and the self-check accepts only the two
  honest reasons ("no lap on this map", "no reference lap" with its tries);
* the hash left out the reference drivers themselves -- it now covers
  LapDriver's margins, the lap and stop rules and every bundled checkpoint's
  sha256, and "bundled" means git-tracked (above);
* the self-check hard-coded 108 classes (a new car or engine mode would have
  failed it for ever) -- now counted from the class lists;
* V31's medal leg would pass with no table at all -- it now requires the
  class to have targets and a lap to earn a medal;
* the stored best medal is reconciled with the medal the PB already earns,
  the lap notes are short enough for the 400 px bottom bar (`NEW PB 1:00.729
  (-0.412) P1/5 GOLD!`), and a lap's place / medal tags no longer come back
  on the HUD when a later note (the TIME TRIAL start) is shown.

Also the sector-order rule and the stall stop above (latent: no author lap
was affected). The table was rebuilt with all of it: the same 81 author
times to the millisecond.

## In the game

`Sim._rec_lap`, the recorder's lap callback, asks `medals.medal_for` for
every valid lap: the lap's HUD note ends `GOLD` (`GOLD!` when it is the
class's best yet; the notes were made shorter so they fit the 400 px bottom
bar: `NEW PB 1:00.729 (-0.412) P1/5 GOLD!`) and the timing panel tags the lap in the medal's colour; the class's
best medal goes into its records file (`RecordBook.set_best_medal`, written
by the recorder's filing thread, `LapRecorder.save_later`, off the step). The
pre-race page shows author / gold / silver / bronze and the best you hold.
V31: its three scripted laps earn `author`, `gold`, `gold` (60.729 / 60.837 /
60.837 against an author of 60.835 -- the V31 car starts rolling before the
line, the reference from a standstill), and the file keeps `author`.

## Staleness

`inputs_hash`: every track definition (both surface settings), every car
spec, the engine scales, the surface modes, the wet scale, the off-track
grip, DT_PHYS and the three multipliers -- and, beyond the brief, the
REFERENCE DRIVERS: LapDriver's margins, the lap rules (full lap, spin), the
stop rules and the sha256 of every bundled checkpoint file. Floats at 10
significant digits (a last-bit difference between machines is not "stale";
paint -- a patch's colour and label -- is left out). A stale table still loads
and still shows medals; the self-check prints `medals are stale: python3 -m
drive.medals --build` as a SOFT fail. `--build --only TRACK` refuses to run
on a stale table (a partial build would stamp it current with the other maps
dropped). NOT covered: the vehicle / powertrain physics and LapDriver's code
-- a physics change must be followed by a rebuild by hand.

"Bundled" checkpoints are the git-tracked ones: a swarm saves the bots a
player breeds into the same `drive/ml/checkpoints/`, and one machine's bot must
not set an author time the repo cannot reproduce. Without git (an installed
game) every file there counts, with a note -- only the build and the
self-check's staleness test ask.
